Comandos de navegación y gestión de archivos

1. Comando touch: Creación y Modificación de Marcas de Tiempo de Archivos

El comando touch se usa principalmente para dos propósitos: crear un archivo vacío o actualizar las marcas de tiempo (acceso, modificación y cambio) de un archivo existente.

Uso Básico: Crear un Archivo

  • Comando: touch archivo.txt

  • Finalidad: Crea un archivo vacío llamado archivo.txt en el directorio actual.

  • Ejemplo Práctico:

touch informe_ventas.doc

ls -l informe_ventas.doc

-rw-rw-r-- 1 jose jose 0 Oct 9 07:00 informe_ventas.doc

Opciones Comunes:

Opción Descripción
-a Solo cambia la hora de acceso (access time).
-m Solo cambia la hora de modificación (modification time).
-t [[CC]YY]MMDDhhmm[.ss] Usa el argumento fecha_hora especificado en lugar de la hora actual.

Ejemplo Práctico: Modificar Solo la Hora de Acceso

  1. Creamos un archivo.

  2. Esperamos unos segundos.

  3. touch con -a y luego comparamos las marcas de tiempo con stat.

touch datos_antiguos.txt

# (Esperar 10 segundos...)

stat datos_antiguos.txt | grep "Acceso\|Modificación"

Acceso: (0664/-rw-rw-r--) Uid: ( 1000/ jose) Gid: ( 1000/ jose)

Acceso: 2025-10-11 08:59:24.256741984 +0200

Modificación: 2025-10-11 08:58:39.417333542 +0200

touch -a datos_antiguos.txt

stat datos_antiguos.txt | grep "Acceso\|Modificación"

Access: 2025-10-09 07:01:10.000000000 +0200 <-- ¡Esta se actualizó!

Modify: 2025-10-09 07:01:00.000000000 +0200 <-- Esta no

El comando stat es una herramienta fundamental en el pentesting que se utiliza principalmente en la fase de post-explotación o durante la escalada de privilegios en sistemas basados en Linux/Unix.

Aunque es un comando simple, la información detallada que proporciona sobre los metadatos de los archivos es crítica para un atacante o pentester.

Usos Clave de stat en Pentesting

El comando stat muestra información detallada sobre el archivo (o inode), incluyendo: permisos, propietario, tamaño, y, lo más importante, las marcas de tiempo (timestamps) de acceso, modificación y cambio de atributos.

1. Detección de Archivos Modificados (Modify/Change Time)

El principal uso es la detección de archivos sospechosos. Un atacante puede usar stat para identificar programas o archivos de configuración que han sido alterados recientemente.

  • Búsqueda de Backdoors o Troyanos: Si un atacante compromete el sistema y deja un backdoor, este archivo tendrá una marca de tiempo de Modificación (Modify) reciente, que no coincide con la fecha de instalación del sistema o la última actualización legítima.

  • Archivos de Configuración: Verificar cuándo se modificó por última vez un archivo crítico como /etc/passwd o /etc/sudoers. Si la hora de Modificación es muy reciente, podría indicar una alteración maliciosa.

stat /etc/passwd

2. Detección de Acceso a Archivos (Access Time)

Esta es crucial para saber si el sistema ha sido revisado, o si un atacante ha leído archivos sensibles.

  • Identificación de Vigilancia: Un administrador de sistemas o pentester puede usar las marcas de tiempo de Acceso (Access) para saber qué archivos o directorios leyó recientemente un usuario o proceso sospechoso.

  • Investigación Forense: Después de ganar acceso (o para ver qué leyó un atacante), revisar la hora de Acceso de archivos importantes como logs, claves (id_rsa), o documentos confidenciales para determinar qué información fue potencialmente comprometida.

stat ~/.ssh/id_rsa

El archivo ~/.ssh/id_rsa es la clave privada SSH que se usa para conectarse a otros servidores de forma segura.

No se crea automáticamente: Este archivo no se crea por defecto cuando instalas un sistema operativo Linux (ni siquiera en una Máquina Virtual).

Se genera bajo demanda: Solo se crea cuando el usuario lo genera explícitamente usando el comando ssh-keygen.

En el ámbito del pentesting, buscar ~/.ssh/id_rsa es un movimiento estándar porque es una de las primeras cosas que un atacante busca al obtener acceso a una máquina.

  • Si existiera, el atacante podría usar esa clave privada para moverse lateralmente (es decir, acceder a otros servidores o máquinas a las que la víctima tiene permiso, sin necesidad de contraseña).

3. Escalada de Privilegios

La información de stat sobre permisos y propiedades del archivo ayuda a identificar potenciales debilidades:

  • Permisos y Propietario: Permite verificar rápidamente los permisos (%a) y el propietario (%U y %G) de un archivo. Si un archivo crítico o un binario del sistema tiene permisos laxos (por ejemplo, escritura para "otros"), podría ser explotado.

stat -c "%n %a %U %G" /usr/bin/comando_sospechoso

  • Archivos SUID/SGID: Aunque el comando find es más eficiente para esto, stat puede confirmar los permisos especiales de ejecución (s) en archivos que pueden llevar a una escalada de privilegios si se ejecutan como root.

El comando stat es una de las herramientas de GNU Core Utilities que, si bien no es una herramienta de pentesting por sí misma (como Nmap o Metasploit), es indispensable en el análisis forense y el reconocimiento interno de un sistema comprometido.

2. Comando file: Determinar el Tipo de Archivo

El comando file examina el contenido de un archivo (no solo su extensión) para determinar su tipo.

Uso Básico: Identificar un Archivo

  • Comando: file nombre_archivo

  • Finalidad: Muestra una descripción del tipo de datos que contiene el archivo.

Ejemplo Práctico:

touch archivo_vacio.txt

echo "Hola, esto es un script" > mi_script.sh

file archivo_vacio.txt

archivo_vacio.txt: empty

file mi_script.sh

mi_script.sh: ASCII text

file /bin/bash

/bin/bash: ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, ...

Opción Común:

Opción Descripción
-s Trabaja con archivos especiales de bloque o carácter (útil para ver el tipo de un sistema de archivos en una partición).

3. Comando stat: Mostrar el Estado Detallado del Archivo

El comando stat muestra información muy detallada sobre el archivo o sistema de archivos, incluyendo los números de i-nodo y las tres marcas de tiempo.

Uso Básico: Ver Metadatos

  • Comando: stat nombre_archivo

  • Finalidad: Muestra el tamaño, permisos, propietario, i-nodo, y las marcas de tiempo Acess, Modify y Change.

  • Ejemplo Práctico:

touch informe_semanal.pdf

stat informe_semanal.pdf

File: informe_semanal.pdf

Size: 0 Blocks: 0 IO Block: 4096 regular empty file

Device: 801h/2049d Inode: 2000001 Links: 1

Access: (0664/-rw-rw-r--) Uid: ( 1000/ jose) Gid: ( 1000/ jose)

Access: 2025-10-09 07:05:00.000000000 +0200

Modify: 2025-10-09 07:05:00.000000000 +0200

Change: 2025-10-09 07:05:00.000000000 +0200

Birth: 2025-10-09 07:05:00.000000000 +0200

Opción Común:

Opción Descripción
-f Muestra el estado del sistema de archivos donde reside el archivo.

4. Comando find: Búsqueda Potente de Archivos

El comando find busca archivos en una jerarquía de directorios que cumplen con una condición dada. Es extremadamente potente y se usa para búsquedas en tiempo real.

Uso Básico: Buscar por Nombre

  • Comando: find ruta -name "patron"

  • Finalidad: Busca un archivo por nombre (distingue mayúsculas/minúsculas) a partir de la ruta.

  • Ejemplo Práctico: Buscar el archivo interfaces en el directorio /etc.

find /etc -name "interfaces"

/etc/cups/interfaces

Opciones Comunes:

Opción Descripción
-iname Busca por nombre ignorando mayúsculas/minúsculas.
-type d Busca solo directorios. Use f para archivos, l para enlaces simbólicos.
-user nombre Busca archivos propiedad del usuario especificado.
-mtime +N/-N Busca archivos modificados hace más de N días (+N) o menos de N días (-N).

sudo find -user jose

sudo find -type d

Ejemplo Práctico: Buscar archivos de configuración que no sean propiedad de jose y que hayan sido modificados en el último día

# Creamos un archivo de prueba con sudo para que sea de root

sudo touch /etc/mi_nuevo_config.conf

# Buscamos en /etc archivos regulares (-type f) que NO sean de 'jose' (-not -user jose) y que hayan sido modificados en el último día (-mtime -1).

find /etc/mi_nuevo_config.conf -type f -not -user jose -mtime -1

5. Comando locate: Búsqueda Rápida de Archivos

El comando locate busca archivos utilizando una base de datos pre-indexada (mlocat.db). Es mucho más rápido que find, pero solo encuentra archivos que existían en el momento de la última actualización de la base de datos.

Uso Básico: Búsqueda Rápida

  • Comando: locate nombre_archivo

  • Finalidad: Busca rápidamente cualquier archivo cuyo nombre contenga la cadena especificada en la base de datos.

  • Ejemplo Práctico:

sudo apt install plocate

locate bashrc | head -3

/etc/bash.bashrc

/etc/skel/.bashrc

/home/jose/.bashrc

Opción Común:

Opción Descripción
-i Ignora mayúsculas/minúsculas.
-c Solo cuenta el número de resultados.

Ejemplo Práctico: Contar archivos que contienen "mysql" (ignorando mayúsculas)

locate -i -c mysql

152

Nota importante: Si un archivo acaba de ser creado, locate no lo encontrará hasta que se actualice la base de datos con el comando sudo updatedb.

6. Comando which: Localizar Comandos Ejecutables

El comando which busca binarios ejecutables (programas) en los directorios listados en la variable de entorno $PATH.

Uso Básico: ¿Dónde está el programa?

  • Comando: which nombre_comando

  • Finalidad: Muestra la ruta completa al binario ejecutable.

  • Ejemplo Práctico:

which ls

/usr/bin/ls

which python3

/usr/bin/python3

Opción Común:

Opción Descripción
-a Imprime todas las coincidencias en el $PATH, no solo la primera.

El comando which se utiliza en pentesting principalmente en las fases de post-explotación y reconocimiento interno para determinar la ubicación absoluta de los binarios ejecutables del sistema.

Su objetivo es la fiabilidad y la evasión.

1. Garantizar la Ejecución Confiable

En un sistema comprometido, el entorno del shell que obtiene el atacante (o pentester) suele ser mínimo y puede no tener la variable de entorno $PATH correctamente configurada.

  • Rutas Absolutas: Al obtener la ruta completa de un comando (ej. /bin/bash en lugar de solo bash), se asegura que el script o el exploit se ejecutará correctamente sin depender de la configuración del $PATH.

Se usa para obtener la ruta del intérprete en una reverse Shell

which python

# Resultado: /usr/bin/python

2. Detección de Modificaciones y Evasión

El comando which ayuda al atacante a evadir posibles trampas o a identificar si los binarios comunes han sido reemplazados.

  • Binarios "Troyanizados": Un administrador de sistemas puede haber reemplazado binarios comunes (como ls, netcat, o incluso which mismo) con versiones modificadas para registrar la actividad del atacante. Al usar which, el atacante ve dónde está el binario que el sistema realmente está ejecutando.

  • Identificación de Herramientas Útiles: Permite comprobar rápidamente si hay herramientas útiles instaladas y disponibles para la escalada de privilegios o movimiento lateral.

    • Saber si existe un compilador (which gcc).

    • Saber si está instalado el intérprete de un lenguaje de scripting avanzado (which perl, which ruby).

    • Saber si están instalados comandos de red avanzados (which nc o which ncat).

En resumen, which es la forma más rápida de obtener conciencia situacional y asegurar que el atacante está llamando a las herramientas que cree que está llamando, en su ubicación exacta.

7. Comando type: Describir un Comando

El comando type describe cómo se interpretará un nombre de comando, indicando si es un alias, una función, un comando incorporado (builtin) o un ejecutable externo.

Uso Básico: Analizar el Tipo

  • Comando: type nombre_comando

  • Finalidad: Muestra el tipo de comando.

  • Ejemplo Práctico:

type ls

ls is aliased to `ls --color=auto' <-- ¡Es un alias!

type cd

cd is a shell builtin <-- ¡Es un comando incorporado del shell!

type find

find is /usr/bin/find <-- ¡Es un ejecutable externo!

Opción Común:

Opción Descripción
-a Muestra todas las formas en las que se podría interpretar el nombre.

8. Comando basename: Extraer el Nombre del Archivo

El comando basename elimina cualquier prefijo de directorio de una ruta dada, dejando solo el nombre del archivo o directorio.

Uso Básico: Extraer el Nombre Final

  • Comando: basename /ruta/al/archivo

  • Finalidad: Muestra el último componente de la ruta.

Ejemplo Práctico:

basename /home/jose/documentos/completo.txt

completo.txt

basename /etc/apt/

apt

Opción Común:

Opción Descripción
[SUFIXO] Elimina un sufijo especificado del nombre del archivo (útil para extensiones).

Ejemplo Práctico: Quitar la extensión

basename /home/jose/completo.txt txt

completo

9. Comando dirname: Extraer el Nombre del Directorio

El comando dirname complementa a basename al eliminar el último componente de la ruta, dejando solo la parte del directorio.

Uso Básico: Extraer la Ruta del Directorio

  • Comando: dirname /ruta/al/archivo

  • Finalidad: Muestra todos los componentes de la ruta excepto el último.

  • Ejemplo Práctico:

dirname /home/jose/completo.txt

/home/jose/

dirname completo.txt

.

dirname /usr/local/bin/

/usr/local

Nota: Cuando se aplica a un archivo en el directorio actual (como completo.txt), devuelve un punto (.), que representa el directorio actual.

Ejercicio final práctico

Supón que tienes este archivo:

/home/jose/proyectos/python/app.py

touch app.py

Vamos a aplicar varios comandos:

basename /home/jose/proyectos/python/app.py

# Resultado: app.py

dirname /home/jose/proyectos/python/app.py

# Resultado: /home/jose/proyectos/python

file /home/jose/proyectos/python/app.py

/home/jose/proyectos/python/app.py: empty

stat /home/jose/proyectos/python/app.py

# Muestra tamaño, fecha, permisos, etc.

find /home/jose/proyectos -name "*.py"

# Encuentra archivos Python

locate app.py

# Encuentra ubicaciones conocidas de "app.py" en el sistema

Seguramente no veremos nuestra app.py.

El problema es que la base de datos de locate aún no se ha actualizado para incluir el archivo que acabas de crear.

1. find (Búsqueda en Tiempo Real)

  • ¿Cómo funciona? find busca archivos directamente en el sistema de archivos, explorando los directorios en tiempo real.

  • Velocidad: Es más lento, especialmente en directorios grandes.

  • Precisión: Es siempre preciso, ya que ve los archivos en el momento exacto en que se ejecuta.

Cuando ejecutas find, encontró inmediatamente /home/jose/proyectos/python/app.py porque lo buscó físicamente en la carpeta.

2. locate (Búsqueda en Base de Datos)

  • ¿Cómo funciona? locate no busca en el disco duro. En su lugar, consulta una base de datos precompilada de todos los archivos del sistema, llamada mlocate.db.

  • Velocidad: Es extremadamente rápido.

  • Precisión: Solo es preciso si la base de datos está actualizada.

  • La base de datos se actualiza automáticamente (normalmente una vez al día o cada pocas horas) o manualmente. Como creamos app.py hace poco, el archivo aún no estaba en la base de datos, por eso no lo listó.

Solución

Para que locate muestre tu archivo, debes forzar la actualización manual de la base de datos ejecutando el comando updatedb con permisos de superusuario:

sudo updatedb

Una vez que este comando termine de ejecutarse (tarda unos segundos), si vuelves a ejecutar locate, ahora sí verás tu archivo:

jose@jose-VirtualBox:~/proyectos/python$ sudo updatedb

jose@jose-VirtualBox:~/proyectos/python$ locate app.py

... (otras rutas de snap y python) ...

/home/jose/proyectos/python/app.py <-- ¡Ahora sí aparece!

which python3

# Te muestra dónde está instalado el ejecutable de Python

type cd

# Te dice que es un comando interno del shell
