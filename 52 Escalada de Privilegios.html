Escalada de Privilegios en Linux: Concepto, Producción y Prevención

1. ¿Qué es la Escalada de Privilegios?

La escalada de privilegios (Privilege Escalation) es un tipo de ataque informático en el que un usuario o proceso con bajos permisos de seguridad (un usuario regular, por ejemplo) obtiene acceso a recursos o funciones que normalmente están restringidas a usuarios con mayores privilegios, como el usuario root (el administrador absoluto del sistema).

El objetivo final de un atacante es siempre obtener acceso de root (o privilegios de administrador) para poder controlar totalmente el sistema: instalar malware, modificar archivos críticos del sistema, acceder a datos de otros usuarios, o usar el servidor como plataforma de ataque a otras redes.

2. Tipos de Escalada

Existen dos categorías principales de escalada:

  1. Escalada Horizontal: Un atacante accede a los recursos o cuenta de otro usuario regular (por ejemplo, el usuario A obtiene acceso a la cuenta del usuario B). Los privilegios no aumentan en nivel, sino en alcance.

  2. Escalada Vertical (o Elevación de Privilegios): Un usuario o proceso con pocos privilegios eleva su estatus al nivel de root. Este es el tipo más peligroso y el foco de la mayoría de los ataques.

3. Mecanismos Comunes de Producción (Vectores de Ataque)

La escalada de privilegios rara vez es el primer paso de un ataque; ocurre después de que un atacante ya ha obtenido un punto de apoyo inicial en el sistema (una Shell de bajo nivel).

A. Archivos y Binarios con Permiso SUID/SGID Mal Configurado

El vector de escalada más clásico.

  • SUID (Set User ID): Cuando este bit está activado en un binario ejecutable, permite que el binario se ejecute con los permisos del dueño del archivo, en lugar de con los permisos del usuario que lo ejecuta.

  • Problema: Si un comando potencialmente peligroso (como find, vim, less o nmap) tiene activado el bit SUID y es propiedad de root, un usuario regular puede ejecutarlo para luego ejecutar comandos de root o incluso abrir una shell de root.

  • Comando de Detección:

find / -type f -perm /4000 2>/dev/null

B. Fallas en el Kernel y Controladores (Vulnerabilidades)

Son las vulnerabilidades más críticas y a menudo las más difíciles de mitigar.

  • Mecanismo: Un atacante explota un error (bug) o una debilidad de seguridad (security flaw) en el código fuente del Núcleo de Linux o en alguno de sus módulos/controladores.

  • Resultado: Esto permite al atacante ejecutar código arbitrario con privilegios de kernel (que son equivalentes a los de root).

  • Solución: Mantener el kernel y los paquetes del sistema siempre actualizados.

C. Mala Configuración del sudo

El archivo /etc/sudoers define qué usuarios pueden ejecutar comandos como root y sin pedir contraseña.

  • Mecanismo: Si un usuario regular tiene permiso para ejecutar un comando que puede ser usado para obtener una shell interactiva (como vi, less, awk, find, o utilidades de gestión de paquetes), puede explotar ese permiso para saltar a una shell de root.

  • Ejemplo de Riesgo: Permitir a un usuario ejecutar solo /usr/bin/find como sudo le permite ejecutar sudo find / -exec /bin/sh \;, lo que le da una shell de root.

D. Credenciales Almacenadas en Archivos (Hardcoded Credentials)

Ocurre a menudo en entornos de desarrollo o scripts mal escritos.

  • Mecanismo: Un atacante encuentra contraseñas o claves de API codificadas (hardcoded) en archivos de configuración, scripts de shell, o variables de entorno que están accesibles para usuarios de bajo privilegio.

  • Archivos típicos de búsqueda: ~/.bash_history, archivos de configuración de bases de datos, ~/.ssh/, o scripts en /var/www/.

4. Medios para Evitar la Escalada de Privilegios

La prevención de la escalada de privilegios se basa en una defensa en profundidad y una configuración estricta.

A. Actualización y Parcheo (La Defensa más Crítica)

  • Mantenimiento del Sistema Operativo y Kernel: Instala siempre los parches de seguridad y mantén el kernel y el software principal del sistema operativo al día. Esto mitiga las vulnerabilidades de tipo B (Fallas en el Kernel).

  • Gestión de Paquetes: Utiliza herramientas como apt update && apt upgrade (Debian/Ubuntu) o dnf upgrade (RHEL/Fedora) para garantizar que todas las aplicaciones críticas estén actualizadas.

B. Gestión Estricta de Permisos

  • Minimizar SUID/SGID: Inspecciona el sistema regularmente y elimina el bit SUID/SGID de cualquier binario que no lo requiera absolutamente, especialmente comandos comunes como find o less.

    • Comando para remover:

sudo chmod u-s /ruta/al/binario

  • Principio del Mínimo Privilegio (PoLP): Los usuarios y las aplicaciones deben tener solo los permisos estrictamente necesarios para realizar su trabajo.

    • Ejemplo: Un servidor web nunca debería ejecutarse como usuario root.

C. Configuración Segura de Sudo

  • Especificidad de Comandos: En el archivo /etc/sudoers, configura el acceso de sudo para que sea lo más específico posible. Nunca permitas a un usuario ejecutar cualquier comando (ALL) a menos que sea el administrador del sistema.

  • Evitar Shells: Evita otorgar permisos de sudo a comandos que puedan ser abusados para abrir una shell de root (como vim, find, less, nmap con ciertas banderas, etc.).

D. Endurecimiento del Sistema (Hardening)

  • SELinux/AppArmor: Habilita y configura un Módulo de Seguridad del Kernel (LSM) como SELinux (Security-Enhanced Linux) o AppArmor. Estos sistemas aplican control de acceso obligatorio (MAC) y restringen lo que incluso un proceso de root puede hacer, limitando el daño si ocurre una escalada.

  • Contraseñas Fuertes: Aplica políticas de contraseñas complejas y asegúrate de que las credenciales no se almacenen en texto plano.

  • Restricción de Historial: Configura el archivo ~/.bash_history para evitar que se guarden ciertos comandos sensibles o que se limite su tamaño.

Configurar el archivo ~/.bash_history para restringir o limitar los comandos guardados es crucial para la seguridad y la prevención de la escalada de privilegios en Linux.

Importancia de Restringir el Historial

El archivo ~/.bash_history (o archivos similares para otras shells como ~/.zsh_history) almacena una lista cronológica de todos los comandos que un usuario ha ejecutado.

Su restricción es importante por las siguientes razones:

  1. Exposición de Credenciales y Datos Sensibles: Un atacante que logra acceder a una cuenta de bajo privilegio puede revisar el historial y encontrar comandos que revelen información confidencial, como:

    • Contraseñas introducidas en la línea de comandos (aunque esto debe evitarse).

    • Claves de API, tokens o URLs con credenciales incrustadas.

    • Nombres de archivos sensibles, rutas ocultas, o IPs privadas.

  2. Mapeo de la Red y el Sistema: El historial puede mostrarle a un atacante qué comandos de diagnóstico ejecutó el usuario (ip a, route, ls -la /etc/, etc.), lo que facilita al atacante el mapeo del sistema, encontrando puntos débiles o configuraciones incorrectas.

  3. Prevención de Pasos: Si un atacante no puede ver cómo se realizaron tareas administrativas específicas, se vuelve más difícil replicar la acción o revertir medidas de seguridad.

Ejemplo Práctico de Configuración

Puedes limitar el tamaño y la duración del historial de bash modificando variables de entorno en el archivo ~/.bashrc.

1. Limitar el Tamaño del Historial

Para reducir la cantidad de comandos que se almacenan (por defecto, suele ser 1000):

Variable Valor Sugerido Propósito
HISTSIZE 2000 Define el número máximo de comandos que se mantendrán en la memoria durante la sesión actual.
HISTFILESIZE 4000 Define el número máximo de líneas en el archivo ~/.bash_history en disco.

Ejemplo a añadir en ~/.bashrc:

# Limita la memoria del historial de la sesión a 2000 comandos

export HISTSIZE=2000

# Limita el archivo en disco a 4000 líneas

export HISTFILESIZE=4000

2. Evitar Guardar Comandos Sensibles

Puedes configurar bash para ignorar comandos que comienzan con un espacio, lo que te permite ejecutar comandos sensibles sin que queden registrados.

Variable Valor Propósito
HISTCONTROL ignorespace Evita que se guarden los comandos que empiezan con un espacio.

Ejemplo a añadir en ~/.bashrc:

# Permite al usuario iniciar comandos con un espacio para evitar registrarlos

export HISTCONTROL=ignorespace

Uso práctico (para el usuario):

Si un usuario necesita cambiar una contraseña, puede escribir un espacio antes del comando para evitar que el password (si estuviera visible) se almacene en el historial:

  • Comando visible en el historial:

ssh user@192.168.1.1

  • Comando NO visible en el historial:

ssh user@192.168.1.1 (observa el espacio antes de ssh)

Después de modificar ~/.bashrc, el usuario debe ejecutar source ~/.bashrc o iniciar una nueva sesión para que los cambios surtan efecto.

E. Monitorización y Detección

  • Auditoría de Registros (Logs): Configura y revisa regularmente los registros de auditoría del sistema (como /var/log/auth.log o journalctl). Busca intentos fallidos de su o sudo, o actividad inusual de archivos SUID.

  • Herramientas de Detección: Utiliza herramientas de monitoreo como Tripwire o AIDE para monitorizar la integridad de los archivos. Estas herramientas alertan si archivos críticos del sistema (especialmente binarios con SUID) son modificados.
