Comandos de Archivado y Compresión

tar, gzip, gunzip, bzip2, xz

Estos comandos se utilizan para combinar múltiples archivos en uno solo (archivado) y/o reducir su tamaño (compresión).

tar: Archivador de Cintas (Archivar y Comprimir)

El comando tar se usa para archivar (unir) varios archivos o directorios en un solo archivo (conocido como tarball o archivo .tar). Puede opcionalmente comprimir el resultado.

Opción Función Descripción
c Create Crea un nuevo archivo .tar.
x eXtract Extrae archivos de un archivo .tar.
v Verbose Muestra los archivos a medida que se procesan.
f File Especifica el nombre del archivo de archivado.
z Gzip Comprime o descomprime usando gzip (crea archivos .tar.gz o .tgz).
j Bjip2 Comprime o descomprime usando bzip2 (crea archivos .tar.bz2).
J J/xz Comprime o descomprime usando xz (crea archivos .tar.xz).

Ejemplo Práctico 1: Archivar y comprimir con gzip

Si quieres archivar y comprimir su directorio Documentos en un solo archivo .tar.gz.

tar -czvf mi_resguardo_2025.tar.gz Documentos/

Documentos/

Documentos/informe.pdf

Documentos/fotos.jpg

... (lista de archivos)

Ejemplo Práctico 2: Extraer archivos

Quieres extraer el archivo recién creado en una nueva carpeta.

mkdir extraccion_temp

cd extraccion_temp/

tar -xzvf ../mi_resguardo_2025.tar.gz

Documentos/

Documentos/informe.pdf

...

gzip y gunzip: Compresión/Descompresión GZIP

gzip comprime un solo archivo, reemplazando el original con la versión .gz. gunzip hace lo opuesto.

Comando Función Descripción
gzip archivo Comprime Crea archivo.gz y elimina el original.
gunzip archivo.gz Descomprime Crea archivo y elimina el .gz.
gzip -d archivo.gz Descomprime Alternativa a gunzip.
gzip -k archivo Keep Comprime archivo.gz pero mantiene el original.

Ejemplo Práctico: Compresión y Descompresión

# Copiamos un archivo grande para el ejemplo

cp /etc/services services

ls -lh services

-rw-r--r-- 1 jose jose 20K Oct 9 07:15 services

gzip services

ls -lh services.gz

-rw-r--r-- 1 jose jose 7.5K Oct 9 07:15 services.gz

¡El original se fue!

gunzip services.gz

ls -lh services

-rw-r--r-- 1 jose jose 20K Oct 9 07:15 services

¡El original regresó!

bzip2 y xz: Compresión Alternativa

Funcionan de manera idéntica a gzip/gunzip, pero utilizan algoritmos que a menudo logran una mejor tasa de compresión (aunque son más lentos).

Comando Archivo resultante Comando de Descompresión
bzip2 archivo archivo.bz2 bzip2 -d archivo.bz2 o bunzip2 archivo.bz2
xz archivo archivo.xz xz -d archivo.xz o unxz archivo.xz

Ejemplo Práctico: Usando xz

# Copiamos de nuevo

cp /etc/services services_xz

xz services_xz

ls -lh services_xz.xz

-rw-r--r-- 1 jose jose 6.8K Oct 9 07:16 services_xz.xz

# ¡Aún más pequeño que gz!

unxz services_xz.xz

ls services_xz

services_xz

2. Comandos de Compresión ZIP (zip, unzip)

El formato ZIP es un estándar multiplataforma muy común, diferente a los formatos nativos de Unix (tar.gz, etc.).

zip: Crear Archivos ZIP

Opción Descripción
-r Recursive: Incluye subdirectorios.
-e Encrypt: Pide una contraseña para el archivo ZIP.

Ejemplo Práctico: Comprimir un directorio con clave

Quieres comprimir la carpeta Trabajo y protegerla con una contraseña.

zip -r -e datos_trabajo.zip Trabajo/

Enter password:

Verify password:

adding: Trabajo/ (stored 0%)

adding: Trabajo/plan.doc (deflated 5%)

...

unzip: Descomprimir Archivos ZIP

Opción Descripción
-d Directory: Especifica el directorio de destino.

Ejemplo Práctico: Descomprimir en un directorio específico

unzip datos_trabajo.zip -d /tmp/datos_temporales

Archive: datos_trabajo.zip

[datos_trabajo.zip] Trabajo/plan.doc password:

extracting: /tmp/datos_temporales/Trabajo/plan.doc

...

3. Comandos de Visualización, Identificación y Manipulación

zcat: Ver Contenido de Archivos Comprimidos

zcat muestra el contenido de archivos comprimidos con gzip sin descomprimirlos permanentemente. Es muy útil para inspeccionar archivos de log comprimidos.

Ejemplo Práctico: Inspeccionar un log comprimido

Si tienes un archivo de log llamado syslog.1.gz:

echo -e 'Oct 10 07:30:05 servidor kernel: [ 2.000000] Linux version 6.5.0\nOct 10 07:31:10 servidor sshd[1234]: Accepted publickey for jose\nOct 10 07:32:15 servidor CRON[5678]: (root) CMD (command -v logrotate)\nOct 10 07:35:20 servidor systemd[1]: logrotate.service: Succeeded.\nOct 10 07:40:30 servidor kernel: [ 45.123456] usb 1-1: new high-speed USB device\nOct 10 07:45:45 servidor sshd[9012]: pam_unix(sshd:session): session closed for user jose' > syslog.1

lo comprimimos:

gzip syslog.1

zcat syslog.1.gz | less

(Esto descomprime temporalmente el contenido del archivo .gz y lo envía al paginador less, permitiendo leerlo sin modificar el archivo original.)

file: Determinar el Tipo de Archivo (Repaso y Expansión)

Este comando ya se cubrió, pero es fundamental en el contexto de archivos comprimidos para identificar formatos desconocidos. Examina el contenido, no la extensión.

Ejemplo Práctico: Identificar un archivo tar.bz2

1. Creamos una carpeta de ejemplo

mkdir datos_ejemplo

echo "Archivo 1" > datos_ejemplo/a.txt

echo "Archivo 2" > datos_ejemplo/b.txt

2. Creamos y comprimimos el archivo tar.bz2

tar -cjvf backup.tar.bz2 datos_ejemplo/

# -c: crear, -j: bzip2, -v: verbose, -f: archivo

file backup.tar.bz2

El comando file examinará los bytes iniciales del archivo y te dirá exactamente lo que es. Deberías ver una salida similar a esta:

backup.tar.bz2: bzip2 compressed data, block size 900k

Ejemplo Práctico: Identificar un ejecutable

file /bin/bash

file /usr/bin/passwd

Cuando ejecutes file /bin/bash, la salida te dirá que el archivo es un ejecutable ELF para la arquitectura de tu sistema (generalmente 64 bits), y especificará que es dinámicamente enlazado.

Aquí tienes un ejemplo de la salida que obtendrás:

/bin/bash: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2, BuildID[sha1]=..., for GNU/Linux 3.2.0, stripped

La información que proporciona file sobre /bin/bash es técnica, pero clave:

  • ELF 64-bit LSB executable:

    • ELF (Executable and Linkable Format): Es el formato de archivo binario estándar utilizado por Linux para ejecutables, código objeto, bibliotecas compartidas y volcados de núcleo (core dumps).

    • 64-bit LSB: Indica que fue compilado para un procesador de 64 bits (como el x86-64) y que utiliza el formato de byte Least Significant Byte (LSB) o Little Endian.

  • dynamically linked: Significa que bash depende de bibliotecas externas para funcionar. Estas bibliotecas se cargan en tiempo de ejecución (cuando se ejecuta el programa), no durante su compilación. Esto ahorra espacio en disco.

  • interpreter /lib64/ld-linux-x86-64.so.2: Es la ruta al cargador dinámico (o linker). Es el programa que se encarga de cargar todas las bibliotecas dinámicas que bash necesita (como la biblioteca C estándar) antes de que pueda ejecutarse.

  • stripped: Significa que los símbolos de depuración y otra información de desarrollo han sido eliminados del binario para reducir su tamaño.

En resumen, el comando file confirma que /bin/bash es un programa binario compilado (no un script) listo para ser ejecutado en tu sistema.

La diferencia a la hora de explotar un buffer overflow entre arquitecturas de 32 bits (x86) y 64 bits (x86-64) es significativa y afecta directamente a cómo se construye y se ejecuta el ataque.

Las principales diferencias radican en el tamaño de los punteros, el uso del registro base de la pila, y la presencia de técnicas de seguridad modernas que son más comunes en 64 bits.

1. Tamaño de los Punteros y Direcciones

Esta es la diferencia más fundamental:

Característica Arquitectura de 32 bits (x86) Arquitectura de 64 bits (x86-64)
Tamaño del Puntero/Dirección 4 bytes (32 bits) 8 bytes (64 bits)
Impacto en el Buffer Se necesitan 4 bytes para sobrescribir el EIP (Instruction Pointer). Se necesitan 8 bytes para sobrescribir el RIP (Instruction Pointer).
Longitud del Payload El shellcode es generalmente más corto. El shellcode es generalmente más largo (más instrucciones).

Implicación: En 64 bits, se requiere el doble de datos para sobrescribir la dirección de retorno en la pila, lo que alarga la parte de la inyección de la dirección en el payload.

2. Convenciones de Llamada y Registros

Las arquitecturas utilizan diferentes registros para pasar argumentos a las funciones, lo que influye en cómo se organiza la pila y cómo se manipulan los datos.

a. Registro Base de la Pila (RBP vs. EBP)

  • 32 bits (x86): Se utiliza el registro EBP (Extended Base Pointer) para acceder a las variables locales y a los argumentos de las funciones. La dirección de retorno se encuentra justo encima de EBP en la pila. La convención clásica de buffer overflow es sobrescribir primero EBP y luego el EIP (Instruction Pointer).

  • 64 bits (x86-64): Se utiliza el registro RBP (Base Pointer). Además, en 64 bits es común que los compiladores utilicen una optimización llamada "frame pointer omission", donde se prescinde del uso de RBP como puntero base para liberar el registro, haciendo que la dirección de retorno esté en una posición más predecible con respecto al inicio del buffer vulnerable.

b. Paso de Argumentos

  • 32 bits: La mayoría de las veces, los argumentos de las funciones se pasan por la pila (stack).

  • 64 bits: Los primeros seis argumentos de una función se pasan a través de registros específicos (RDI, RSI, RDX, RCX, R8, R9), y solo los argumentos adicionales se colocan en la pila.

Implicación: En 64 bits, la pila no contiene tantos argumentos ni el registro base de manera tan consistente, lo que hace que la posición de la dirección de retorno sea a veces más simple de calcular, pero requiere que el shellcode se adapte a estas convenciones de registros.

Conclusión: La explotación de buffer overflows en 64 bits es técnicamente más compleja, no solo porque se manipulan punteros de 8 bytes, sino porque requiere el uso casi obligatorio de técnicas avanzadas (como ROP y ROP chaining) para sortear las sólidas implementaciones de NX/DEP y ASLR.

dd: Conversión y Copia de Archivos de Bajo Nivel

El comando dd se utiliza para copiar y convertir datos de un lugar a otro, byte a byte. Es extremadamente poderoso (y peligroso si se usa incorrectamente) y se usa comúnmente para crear imágenes de disco, grabar ISOs, o realizar copias de seguridad a nivel de bloque.

¡Advertencia! El uso incorrecto de dd puede sobrescribir particiones del sistema.

Opción Función Descripción
if= Input File Especifica el archivo de entrada (source).
of= Output File Especifica el archivo de salida (destination).
bs= Block Size Establece el tamaño de bloque para la lectura/escritura (ej. 4M).
status=progress Muestra el progreso de la copia.

Ejemplo: Crear una imagen de un disco (requiere sudo)

Si quieres crear una imagen del primer disco duro (/dev/sda) en un archivo, copiando bloques y mostrando el progreso.

sudo dd if=/dev/sda of=/mnt/usb/sda_image.img bs=4M status=progress

450+0 records in

450+0 records out

1887436800 bytes (1.9 GB, 1.8 GiB) copied, 32.545 s, 58.0 MB/s

(Generalmente, if se dirige a un dispositivo de disco y of a un archivo, o viceversa, dependiendo de si se está creando una imagen o escribiéndola.)

Ejemplo Práctico: Crear un archivo de 100MB relleno de ceros

Útil para pruebas o crear archivos swap:

dd if=/dev/zero of=archivo_vacio.dat bs=1M count=100

100+0 records in

100+0 records out

104857600 bytes (105 MB, 100 MiB) copied, 0.04 s, 2.6 GB/s

(Aquí, if=/dev/zero es un dispositivo especial que proporciona un flujo interminable de bytes nulos.)

Parte del Comando Significado Propósito en el Ejemplo
dd Data Duplicator El comando principal para la copia a nivel de bloque.
if=/dev/zero Input File (Archivo de Entrada) Es una fuente virtual que solo produce el carácter nulo (cero binario) indefinidamente.
of=archivo_vacio.dat Output File (Archivo de Salida) Es el nombre del archivo que se va a crear en tu directorio actual.
bs=1M Block Size (Tamaño de Bloque) Establece que cada lectura y escritura se hará en bloques de 1 Megabyte.
count=100 Count (Conteo) Indica que se deben escribir 100 de estos bloques de 1MB.

1 MB/bloque×100 bloques=100 MB

Después de ejecutar el comando, puedes usar ls -lh para confirmar que el archivo tiene el tamaño correcto:

ls -lh archivo_vacio.dat

Resultado esperado:

-rw-r--r-- 1 jose jose 100M Oct 10 08:45 archivo_vacio.dat

1. tar – Archivar y comprimir archivos y carpetas

Sintaxis general:

tar [opciones] archivo.tar [archivos/directorios]

Opciones comunes:

  • -c: crear

  • -x: extraer

  • -t: listar contenido

  • -v: modo detallado (verbose)

  • -f: nombre del archivo

  • -z: usar gzip

  • -j: usar bzip2

  • -J: usar xz

Ejemplos prácticos:

Crea el directorio y algunos archivos de ejemplo:

mkdir -p /home/jose/documentos/informes

echo "Reporte 1" > /home/jose/documentos/documento_a.txt

echo "Informe de ventas" > /home/jose/documentos/informes/ventas_2025.txt

Ejecuta el comando tar para crear el archivo:

tar -cvf backup.tar /home/jose/documentos/

^

|--- ¡La ruta comienza en la raíz (/)!

Cuando tar ve que la ruta de origen comienza con la barra / (indicando que es una ruta que comienza en la raíz), automáticamente elimina esta barra inicial del nombre de los archivos dentro del archivo backup.tar.

¿Por qué lo hace? (Seguridad y Portabilidad)

  1. Seguridad (Sobrescritura Accidental): Si tar incluyera la barra / en los nombres de los archivos archivados, al descomprimir el archivo (tar -xvf backup.tar), el sistema intentaría escribir los archivos en su ruta original. Por ejemplo, el archivo /home/jose/documentos/documento_a.txt se intentaría extraer exactamente a esa ubicación en el sistema. Si el archivo lo descomprime otro usuario, esto podría sobrescribir archivos del sistema de forma peligrosa o accidental.

  2. Portabilidad: Al eliminar la barra /, los archivos se extraen de forma segura en una ruta relativa al directorio donde se ejecuta el comando de extracción. Esto garantiza que el archivo de respaldo pueda ser movido y restaurado en cualquier parte del sistema sin riesgo.

Crear un archivo comprimido con gzip (.tar.gz):

tar -czvf backup.tar.gz /home/jose/documentos/

Extraer un .tar.gz:

tar -xzvf backup.tar.gz

Listar contenido sin extraer:

tar -tvf backup.tar.gz

Extraer archivo a carpeta específica:

tar -xzvf backup.tar.gz -C /home/jose/restaurar/

2. gzip – Comprimir archivos individuales

Uso:

gzip archivo

Ejemplos prácticos:

Comprimir un archivo:

gzip /home/jose/notas.txt

# Crea notas.txt.gz y elimina el original

Mantener el original:

gzip -k /home/jose/notas.txt

Ver compresión sin comprimir:

gzip -l /home/jose/notas.txt.gz

3. gunzip – Descomprimir archivos .gz

Uso:

gunzip archivo.gz

Ejemplo práctico:

Descomprimir:

gunzip /home/jose/notas.txt.gz

4. bzip2 – Compresión más eficiente (pero más lenta)

Uso:

bzip2 archivo

Comprimir:

bzip2 /home/jose/logs.txt

# Crea logs.txt.bz2

Mantener el original:

bzip2 -k /home/jose/logs.txt

Descomprimir con bunzip2:

bunzip2 logs.txt.bz2

5. xz – Alta compresión, similar a bzip2 pero más moderno

Uso:

xz archivo

Comprimir:

xz /home/jose/grande.txt

# Crea grande.txt.xz

Mantener original:

xz -k grande.txt

Descomprimir:

unxz grande.txt.xz

6. zip – Comprimir archivos con formato .zip

Uso:

zip archivo.zip archivo1 archivo2 ...

Ejemplos:

Comprimir varios archivos:

zip documentos.zip /home/jose/archivo1.txt /home/jose/archivo2.txt

Comprimir recursivamente un directorio:

zip -r documentos.zip /home/jose/documentos/

7. unzip – Extraer archivos .zip

Uso:

unzip archivo.zip

Extraer en carpeta específica:

unzip documentos.zip -d /home/jose/restaurar/

8. zcat – Ver el contenido de un archivo .gz sin descomprimir

Uso:

zcat archivo.gz

Ejemplo:

Ver contenido de logs comprimidos:

zcat /var/log/syslog.1.gz | less

El archivo syslog.1.gz existe en un sistema Linux estándar, pero es un archivo temporal y rotado.

Cuándo Existe syslog.1.gz

En un sistema Linux que ha estado funcionando por un tiempo, el archivo syslog.1.gz existe si el servicio logrotate ha hecho su trabajo.

  1. logrotate es una utilidad del sistema que gestiona automáticamente los archivos de log (registro) para evitar que crezcan indefinidamente.

  2. Cuando el archivo syslog principal alcanza cierto tamaño o edad, logrotate le cambia el nombre a syslog.1 y lo comprime (usando gzip) para ahorrar espacio, convirtiéndolo en syslog.1.gz.

  3. El sistema sigue escribiendo nuevos registros en un nuevo archivo syslog.

  4. En la siguiente rotación, syslog.1.gz podría convertirse en syslog.2.gz, y así sucesivamente.

Conclusión: Si estás en un servidor o una máquina virtual que ha estado en uso, es muy probable que exista en la ruta /var/log/syslog.1.gz.

Cuándo hay que Crearlo para Practicar

Si estás usando una máquina virtual recién instalada o una máquina que nunca ha pasado por la rotación de logs, el archivo syslog.1.gz podría no existir todavía.

  1. Verificar primero: Comprueba si el archivo ya existe y si tienes permisos para leerlo:

ls -lh /var/log/syslog.1.gz

  1. Si existe, usa el comando con sudo:

sudo zcat /var/log/syslog.1.gz | less

  1. Si no existe, sigue los pasos que te di anteriormente para crear un archivo de prueba llamado syslog.1.gz en tu directorio personal para practicar, sin depender de los archivos del sistema:

echo "Línea de prueba 1" > syslog.1

gzip syslog.1

9. file – Detectar tipo de archivo

Aquí lo aplicamos a archivos comprimidos:

file backup.tar.gz

# Resultado: gzip compressed data

file backup.zip

# Resultado: Zip archive data

10. dd – Copiar y convertir archivos a bajo nivel (¡muy potente y peligroso!)

Uso:

dd if=origen of=destino [opciones]

Ejemplos prácticos:

Copiar un archivo:

dd if=/home/jose/iso/original.iso of=/home/jose/iso/copia.iso bs=4M status=progress

Crear un archivo de 100 MB lleno de ceros:

dd if=/dev/zero of=/home/jose/archivo_ceros.bin bs=1M count=100

Hacer copia exacta de un dispositivo (ej: USB):

sudo dd if=/dev/sdb of=/home/jose/usb_backup.img bs=4M status=progress

¡Ten mucho cuidado con dd, puedes sobrescribir discos si te equivocas!

Supón que quieres:

  1. Crear una carpeta con archivos

  2. Comprimirla en varios formatos

  3. Extraerla

  4. Ver los contenidos sin descomprimir

  5. Usar file para inspeccionar
