Comandos para Identificar Usuarios: who y w

Estos comandos te permiten saber quién está conectado al sistema.

1. who (Quién está conectado)

Muestra información básica sobre los usuarios actualmente conectados.

Comando Descripción
who Lista el nombre de usuario, la línea de terminal y la hora de conexión.
who -r Muestra el nivel de ejecución (runlevel) del sistema.
who -b Muestra la hora de la última vez que se arrancó (boot) el sistema.

Ejemplos Prácticos:

  1. Ver quién está en el sistema:

who

jose tty7 2025-10-11 09:00 (:0)

otro_usr pts/1 2025-10-11 09:15 (192.168.1.10)

  1. Ver el nivel de ejecución actual:

who -r

run-level 5 2025-10-11 09:00

El comando who -r en sistemas Linux/Unix (como Ubuntu/Debian) se utiliza para reportar el nivel de ejecución (runlevel) actual del sistema.

La salida suele ser una sola línea que indica cómo se inició el sistema, lo cual es fundamental para el diagnóstico del sistema y la administración de servicios.

Significado de la Salida de who -r

La salida típicamente incluye lo siguiente (aunque el formato puede variar ligeramente entre distribuciones):

Campo Ejemplo Común Descripción
runlevel runlevel La palabra clave que indica que la información se refiere al nivel de ejecución.
[nivel_anterior] N El nivel de ejecución anterior. N significa Ninguno (el sistema acaba de arrancar) o el nivel desde el que se cambió (por ejemplo, 3 si se cambió desde el modo multiusuario sin interfaz gráfica).
[nivel_actual] 5 ó 3 El nivel de ejecución actual. Este número es el más importante.
[fecha] 2025-10-17 La fecha en que se inició este nivel de ejecución.
[hora] 09:47 La hora a la que se inició este nivel de ejecución.

Aunque los sistemas modernos que usan systemd (como su VirtualBox con Ubuntu) han reemplazado los niveles de ejecución numéricos por "targets" (ej. graphical.target), el comando who -r aún proporciona los números tradicionales:

Nivel Nombre Tradicional Significado Típico
0 Halt Apagado del sistema.
1 Single-User Mode Modo de usuario único (mantenimiento, no hay red, pocos servicios).
2 Multi-User Mode (sin GUI) Modo multiusuario, servicios de red activos, sin interfaz gráfica.
3 Multi-User Mode (sin GUI) Similar al nivel 2 o 4 (depende de la distro).
4 No Usado Reservado.
5 Multi-User Mode (con GUI) Modo gráfico multiusuario. Es el modo de escritorio normal.
6 Reboot Reinicio del sistema.

Si tu VirtualBox ha arrancado con un escritorio gráfico (la interfaz de usuario normal), el nivel de ejecución que verás probablemente será 5.

2. w (Quién está y qué están haciendo)

Proporciona la misma información que who, pero añade datos sobre la carga del sistema y el proceso actual que está ejecutando cada usuario.

Comando Descripción
w Muestra un resumen de la carga y qué procesos están activos.
w -h Omite la cabecera (header) con la información de la carga del sistema.
w jose Muestra información solo del usuario jose.

Ejemplos Prácticos:

  1. Ver quién está y qué hace:

W

09:43:05 up 43 min, 2 users, load average: 0.10, 0.15, 0.12

USER TTY FROM LOGIN@ IDLE JCPU PCPU WHAT

jose tty7 :0 09:00 43m00s 0.58s 0.15s /usr/libexec/gnome-terminal

otro_usr pts/1 192.168.1.10 09:15 1m00s 0.05s 0.02s bash

(Nota: La cabecera muestra la hora, tiempo de actividad (up), número de usuarios y la carga media (load average).)

  1. Ver solo la actividad de jose (sin cabecera):

w -h jose

jose tty7 :0 09:00 43m00s 0.58s 0.15s /usr/libexec/gnome-terminal

Comandos de Historial y Monitoreo: history y watch

3. history (Historial de Comandos)

Muestra los comandos ejecutados previamente por el usuario actual. Es vital para auditar tareas y reutilizar comandos complejos.

Comando Descripción
history Muestra todo el historial numerado.
history 10 Muestra solo las últimas 10 líneas del historial.
!123 Ejecuta el comando número 123 del historial.
!ls Ejecuta el último comando que comenzó con ls.

Ejemplos Prácticos:

  1. Mostrar las últimas 5 acciones:

history 5

996 who -r

997 w -h jose

998 cat /etc/hosts

999 pwd

1000 history 5

  1. Volver a ejecutar el comando con el número 998:

!998

cat /etc/hosts

127.0.0.1 localhost

127.0.1.1 Ubuntu2404

...

4. watch (Ejecutar Comandos Repetidamente)

Ejecuta un comando de forma repetitiva y muestra la salida a pantalla completa, permitiendo monitorizar los cambios a lo largo del tiempo.

Comando Descripción
watch <comando> Ejecuta el comando cada 2 segundos por defecto.
watch -n 5 <comando> Ejecuta el comando cada 5 segundos.
watch -d <comando> Resalta los cambios (-d de difference) entre las actualizaciones.

Ejemplos Prácticos:

  1. Monitorizar la actividad de los usuarios cada 2 segundos (presiona Ctrl+C para salir):

watch w

  1. Ver la carga del sistema cada 5 segundos y resaltar si cambia:

watch -n 5 -d "cat /proc/loadavg"

Comandos de Localización: whereis y which

5. whereis (Localizar Binarios, Manuales y Fuente)

Busca un comando en directorios estándar del sistema para encontrar su binario, su código fuente y su página de manual.

Comando Descripción
whereis <comando> Busca binario, manual y fuente.
whereis -b <comando> Busca solo el binario.
whereis -m <comando> Busca solo la página de manual.

Ejemplos Prácticos:

  1. Encontrar todos los componentes del comando bash:

whereis bash

bash: /usr/bin/bash /usr/share/man/man1/bash.1.gz

  1. Encontrar solo la página de manual de df:

whereis -m df

df: /usr/share/man/man1/df.1.gz

6. which (Localizar el Ejecutable en el PATH)

Busca la ruta completa del archivo ejecutable que se usará cuando se escribe el comando, comprobando solo los directorios en la variable $PATH.

Comando Descripción
which <comando> Muestra la ruta del primer ejecutable encontrado en el $PATH.
which -a <comando> Muestra todas las rutas encontradas en el $PATH.

Ejemplos Prácticos:

  1. Ver qué python3 se ejecuta por defecto:

which python3

/usr/bin/python3

  1. Ver si hay múltiples ejecutables de cat en el PATH:

which -a cat

/usr/bin/cat

/bin/cat

(Nota: Esto es común en sistemas que mantienen enlaces simbólicos o binarios en múltiples ubicaciones tradicionales).

Comandos de Shell: alias y unalias

7. alias (Crear Atajos)

Permite crear un nombre más corto o una combinación de opciones para un comando, facilitando su uso.

Comando Descripción
alias Muestra todos los alias actualmente definidos.
alias <nombre>='<comando>' Crea un nuevo alias temporal.

Ejemplos Prácticos:

  1. Crear un alias temporal para ver la información de la red de forma corta:

alias netinfo='ip a'

netinfo

# ... Se ejecuta 'ip a'

(Este alias solo durará hasta que se cierre la sesión de la terminal).

  1. Crear un alias para el comando ls que siempre liste en formato largo y legible (como ll):

alias ll='ls -lh'

ll

8. unalias (Eliminar Atajos)

Elimina un alias previamente definido.

Comando Descripción
unalias <nombre> Elimina el alias especificado.
unalias -a Elimina todos los alias definidos por el usuario.

Ejemplo Práctico con jose:

  1. Eliminar el alias netinfo creado anteriormente:

unalias netinfo

netinfo

bash: netinfo: no se encontró la orden

Comando de Programación: at

9. at (Ejecutar Comandos en un Momento Específico)

Programa un comando para que se ejecute una sola vez en un momento futuro especificado.

Comando Descripción
at <hora> Entra en modo de programación. Termina con Ctrl+D.
at -l o atq Muestra la lista de trabajos en la cola (at queue).
at -r <job_number> o atrm <job_number> Elimina el trabajo de la cola.

sudo apt install at

Asegúrate de que tu terminal acepta mensajes:

mesg y

El comando mesg y no te da ninguna salida porque, cuando se ejecuta correctamente, su única función es activar silenciosamente la recepción de mensajes en tu terminal.

Si no te devuelve ningún error, puedes asumir que la configuración se ha aplicado correctamente y que tu terminal (pts/0 o la que estés usando) ahora está preparada para recibir mensajes del comando write (que es el que usa el comando at).

Ejemplos Prácticos:

  1. Programar un mensaje para dentro de 2 minutos:

at now + 2 minutes

warning: commands will be executed using /bin/sh

at> echo "¡ÉXITO! Esto se fue al mail"

at> <EOT>

at> <Ctrl+D>

job 1 at Sat Oct 11 10:48:00 2025

  1. Listar el trabajo programado:

atq

1 Sat Oct 11 10:48:00 2025 a jose

(El número 1 es el ID del trabajo).

  1. Eliminar el trabajo con ID 1:

atrm 1

sudo apt install mailutils

Después de que se ejecute, comprueba tu correo de sistema con el comando mail:

mail

Para leer el mensaje, simplemente escribe el número de mensaje que quieres ver y presiona Enter.

sh: 54: Syntax error: newline unexpected

1. Salida Estándar (stdout)

¡ÉXITO! Esto se fue al mail

  • Significado: Esta es la salida de tu comando echo. Muestra que la primera parte de tu job sí se ejecutó correctamente. Esto confirma que el servicio at funciona y que la tarea se ejecutó a la hora programada.

2. Salida de Error Estándar (stderr)

sh: 54: Syntax error: newline unexpected

  • Significado: Este es el error de sintaxis que te causó que no vieras el mensaje en la terminal en tu primer intento.

  • Contexto: Cuando ejecutaste el comando at por primera vez, intentaste redirigir la salida a un directorio:

at> echo "..." > /dev/pts/

El shell (/bin/sh) que usa at ejecutó la línea. Dado que /dev/pts/ es un directorio, el shell no pudo redirigir la salida y generó un error de sintaxis al intentar interpretar el comando. Este error, al igual que la salida de echo, fue capturado por at y enviado a tu correo.

Conclusión del correo:

  1. El job se ejecutó.

  2. El echo funcionó (como viste en la primera línea).

  3. La redirección falló debido a un error de sintaxis relacionado con intentar escribir en un directorio (/dev/pts/) o, en el caso de tu primer intento, con un comando incompleto o mal formado.

Para salir del programa mail:

Escribe q en el prompt ? y presiona Enter para volver a la terminal.

? q

Nota:

at> echo "¡EL MENSAJE DE AT LLEGÓ A TIEMPO, JOSE!" | write jose

No suele funcionar porque el comando write es muy sensible y a menudo falla cuando se ejecuta desde un servicio en segundo plano como atd, ya que le cuesta determinar cuál de las sesiones activas (tty o pts) pertenece al usuario jose.

at> echo "¡PRUEBA CON WALL EXITOSA!" | wall

El comando wall (write all) es mucho más robusto para enviar mensajes a todas las terminales activas y no requiere que el servicio de correo esté instalado ni se ve afectado por las restricciones de write.

Aun así, el mensaje no aparece en tu terminal a la hora programada, porque el demonio atd (el servicio que ejecuta las tareas) tiene una configuración de seguridad que le impide enviar mensajes a tu terminal actual, aunque esté activo.

Si quieres que aparezca directamente en tu terminal (y esta permanezca abierta):

  1. Ejecuta el comando tty para obtener el nombre exacto de tu terminal:

tty

# Salida típica: /dev/pts/0 o /dev/tty1

  1. Usa esa ruta exacta en el comando at:

at now + 2 minutes

at> echo "¡ÉXITO! MENSAJE MOSTRADO" > /dev/pts/0

at> <EOT>

Comandos de Diagnóstico Avanzado

1. strace (Rastreo de Llamadas al Sistema)

El comando strace intercepta y registra las llamadas al sistema (syscalls) que un programa hace al kernel de Linux y las señales que recibe. Es fundamental para depurar y entender cómo se comporta un programa.

Opción Común Descripción
strace <comando> Inicia el rastreo del programa especificado.
strace -p <PID> Adjunta strace a un proceso que ya se está ejecutando (por su ID de proceso - PID).
strace -o <archivo> <comando> Guarda toda la salida del rastreo en un archivo en lugar de mostrarla en la pantalla.
strace -c <comando> Cuenta el tiempo, número de llamadas y errores para cada llamada al sistema.

Ejemplos Prácticos:

  1. Rastrear las llamadas que hace el comando ls al kernel:

strace ls -l /tmp

# ... Verás una larga lista de llamadas (openat, read, stat, write, close, etc.)

# ... y al final, la salida normal de 'ls -l /tmp'

  1. Contar las llamadas al sistema al ejecutar un comando simple (más útil para análisis):

strace -c date

Sun Oct 12 10:00:00 AM CEST 2025

% time seconds usecs/call calls errors syscall

------ ----------- ----------- --------- --------- ----------------

90.00 0.000090 3 30 fstat

...

------ ----------- ----------- --------- --------- ----------------

100.00 0.000100 - 150 4 total

Aquí verás un resumen tabular del rendimiento.

2. lsof (Listar Archivos Abiertos)

El comando lsof lista todos los archivos que están siendo utilizados por procesos activos. En Linux, un "archivo" puede ser un archivo regular, un socket de red, un directorio, una librería compartida o un pipe.

Opción Común Descripción
lsof Lista todos los archivos abiertos en el sistema (requiere sudo a menudo).
lsof -i Muestra todos los sockets de red (conexiones de Internet) abiertos.
lsof -u <usuario> Muestra los archivos abiertos por un usuario específico (e.g., lsof -u jose).
lsof +D <directorio> Lista todos los archivos abiertos dentro de un directorio (y sus subdirectorios).

Ejemplos Prácticos:

  1. Ver qué archivos y sockets está utilizando el usuario jose:

lsof -u jose | less

# Puedes ver todos los binarios, librerías y puertos que jose tiene abiertos. Es posible que necesites sudo y que durante la ejecución no veas que te pide la contraseña; hay que ponerla…

  1. Ver qué procesos están usando el puerto 22 (SSH):

sudo lsof -i :22

COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME

sshd 1234 root 3u IPv4 12345 0t0 TCP *:ssh (LISTEN)

sudo lsof -i :22

sudo lsof -i :23

sudo lsof -i :80

Si el comando sudo lsof -i :22 no devuelve ninguna salida, significa que no hay ningún programa (demonio) escuchando activamente conexiones entrantes en el puerto 22 en este momento.

Comandos de Manipulación de Texto y Flujo de Datos

3. tee (Redirección Doble)

El comando tee lee la entrada estándar (stdin) y la escribe simultáneamente a la salida estándar (stdout) y a uno o más archivos. Esto te permite ver la salida de un comando mientras la guardas.

Opción Común Descripción
<comando> | tee <archivo> Escribe la salida del comando al archivo, pero también la muestra en pantalla.
<comando> | tee -a <archivo> Añade (-a de append) la salida al final del archivo existente.

Ejemplos Prácticos:

  1. Ver la lista de directorios y guardarla en un archivo al mismo tiempo:

ls -l /etc | tee lista_etc.txt

# La salida se muestra en la terminal Y se guarda en 'lista_etc.txt'.

  1. Añadir nueva información (la fecha) a un log existente sin sobreescribirlo:

echo "--- Fin de la Sesión ---" | tee -a lista_etc.txt

4. col (Filtro de Pipes)

El comando col filtra caracteres de retroceso y espacios en blanco de la entrada. Su uso más común es para procesar la salida de comandos que están diseñados para terminales antiguas (como man) que usan caracteres especiales de control.

Opción Común Descripción
<comando> | col -b Elimina los caracteres de retroceso y los espacios en blanco (-b de binary), dejando solo texto.

Ejemplo Práctico:

  1. Limpiar la salida de la página man del comando ls antes de guardarla:

man ls | col -b > manual_ls_limpio.txt

# Esto elimina los caracteres de formato para que 'manual_ls_limpio.txt' sea texto plano limpio y fácil de leer o imprimir.

5. fmt (Reformatear Texto)

El comando fmt es un formateador de texto que se utiliza para ajustar el ancho de línea de un archivo o entrada. Es útil para hacer que los archivos de texto (como archivos README o emails largos) sean más legibles.

Opción Común Descripción
fmt <archivo> Reformatea el archivo de entrada (ancho de 75 caracteres por defecto).
fmt -w <número> <archivo> Establece el ancho máximo de la línea en <número> (e.g., -w 50).

Ejemplo Práctico:

  1. Crear un texto de ejemplo:

echo "Esta es una frase muy larga que no respeta ningún ancho de línea y se extiende hasta donde le da la gana a jose." > largo.txt

  1. Reformatear el archivo para que tenga un máximo de 40 caracteres por línea:

fmt -w 40 largo.txt

Esta es una frase muy larga que

no respeta ningún ancho de línea

y se extiende hasta donde le da

la gana a jose.

Comandos de Terminal y Redes

6. tput (Manipulación de la Terminal)

El comando tput se utiliza para interactuar con la base de datos de capacidades de la terminal (terminfo). Permite mover el cursor, cambiar colores, borrar la pantalla, etc., lo que es crucial para scripts de shell interactivos.

Opción Común Descripción
tput clear Borra la pantalla de la terminal.
tput cup <fila> <columna> Mueve el cursor a la posición especificada.
tput bold Activa el modo de texto en negrita.
tput setaf <num> Establece el color de primer plano (e.g., setaf 1 para rojo).

Ejemplo Práctico (en un script simple o en la línea de comandos):

  1. Borrar la pantalla y colocar un mensaje en negrita en el centro:

tput clear; tput cup 10 30; tput bold; echo "¡ATENCIÓN JOSE!"

7. nc (netcat - El Cuchillo Suizo de las Redes)

netcat (nc) es una utilidad que puede leer y escribir datos a través de conexiones de red utilizando los protocolos TCP o UDP. Es una herramienta esencial para pruebas, diagnósticos de red y transferencia simple de datos.

Opción Común Descripción
nc -l -p <puerto> Inicia nc en modo escucha (-l) en un puerto específico.
nc <host> <puerto> Se conecta a un puerto de un host remoto.
nc -z <host> <puerto-rango> Escanea puertos de forma simple (-z de zero-I/O).

Ejemplos Prácticos:

  1. Probar si el puerto 80 (HTTP) está abierto en el servidor de Google (Escaneo básico de puertos):

nc -zv google.com 80

Connection to google.com 80 port [tcp/http] succeeded!

  1. Crear un "Chat" o una conexión simple para transferir texto (requiere dos terminales):

    • Terminal 1 (Escucha):

nc -l -p 8888

  • Terminal 2 (Conecta):

nc localhost 8888

Hola, ¿me oyes?

El texto de la Terminal 2 aparecerá en la Terminal 1, y viceversa.

Comandos de Archivos y Versiones: diff y patch

1. diff (Mostrar Diferencias)

El comando diff compara dos archivos de texto línea por línea y muestra las diferencias. Es fundamental para el control de versiones y la auditoría de configuraciones.

Opción Común Descripción
diff <archivo1> <archivo2> Muestra las diferencias en formato estándar.
diff -u <archivo1> <archivo2> Muestra las diferencias en formato unificado (más fácil de leer y usar con patch).
diff -r <dir1> <dir2> Compara directorios recursivamente.

Ejemplos Prácticos:

  1. Crear dos archivos con una pequeña diferencia:

echo "Linea 1 de codigo" > file_v1.txt

cat file_v1.txt

echo "Linea 2 de codigo modificado" > file_v2.txt

cat file_v2.txt

echo "Linea 3 de codigo" >> file_v1.txt

diff file_v1.txt file_v2.txt

  1. Generar un archivo de diferencias (patch) usando el formato unificado (-u):

diff -u file_v1.txt file_v2.txt > mi_cambio.patch

cat mi_cambio.patch

--- file_v1.txt 2025-10-12 10:00:00.000000000 +0200

+++ file_v2.txt 2025-10-12 10:01:00.000000000 +0200

@@ -1,3 +1,3 @@

Linea 1 de codigo

-Linea 2 de codigo

+Linea 2 de codigo modificado

Linea 3 de codigo

2. patch (Aplicar Cambios)

El comando patch aplica las diferencias generadas por diff (típicamente en formato unificado) a un archivo, revirtiéndolo o actualizándolo.

Opción Común Descripción
patch <archivo> < patchfile Aplica el parche al archivo original.
patch -R <archivo> < patchfile Revierte (-R de reverse) los cambios aplicados por el parche.

Ejemplos Prácticos:

  1. Aplicar el parche mi_cambio.patch a file_v1.txt para convertirlo en file_v2.txt:

# 1. Recreamos file_v1.txt con su contenido original:

echo "Linea 1 de codigo" > file_v1.txt

echo "Linea 3 de codigo" >> file_v1.txt

# 2. Generamos el parche mi_cambio.patch a partir de la diferencia entre v1 y v2:

diff -u file_v1.txt file_v2.txt > mi_cambio.patch

# 3. Aplicamos el parche a file_v1.txt:

patch file_v1.txt < mi_cambio.patch

Resultado: patching file file_v1.txt

# 4. Verificamos el contenido de file_v1.txt:

cat file_v1.txt

Salida Esperada de cat

Linea 1 de codigo

Linea 2 de codigo modificado

Linea 3 de codigo

  1. Revertir el cambio (devolver file_v1.txt a su estado original):

patch -R file_v1.txt < mi_cambio.patch

Resultado: patching file file_v1.txt

Verificamos el contenido de file_v1.txt:

cat file_v1.txt

lscpu Muestra toda la información disponible.
lscpu -e Muestra la información de la CPU en formato extendido/tabular (útil para sistemas multi-CPU/multi-núcleo).

Opción Común Descripción
lspci Lista todos los dispositivos PCI de forma breve.
lspci -nn Muestra los identificadores de vendor y device en formato numérico (útil para buscar drivers).
lspci -k Muestra el módulo del kernel que está siendo usado por cada dispositivo.

Comandos de Gestión de Almacenamiento

5. df (Disk Free)

Muestra información sobre la utilización del espacio en disco de los sistemas de archivos montados.

Opción Común Descripción
df Muestra el uso del disco en bloques de 1K.
df -h Muestra el uso del disco en formato legible por humanos (-h, e.g., MB, GB).
df -T Incluye la columna de tipo de sistema de archivos (e.g., ext4, xfs).

Ejemplo Práctico:

  1. Ver el espacio libre en todos los discos en formato legible:

df -hT

Filesystem Type Size Used Avail Use% Mounted on

/dev/sda2 ext4 98G 15G 78G 16% /

tmpfs tmpfs 3.9G 0 3.9G 0% /dev/shm

/dev/sda1 vfat 511M 6.1M 505M 2% /boot/efi

6. du (Disk Usage)

Estima el espacio utilizado por archivos y directorios de forma recursiva.

Opción Común Descripción
du Muestra el uso del disco para el directorio actual en bloques.
du -h Muestra el uso del disco en formato legible por humanos.
du -sh <directorio> Muestra el total sumado (-s de summarize) del directorio en formato legible.

Ejemplo Práctico:

  1. Ver cuánto espacio está ocupando el directorio de Descargas:

Comandos de Procesos y Transferencia

7. nohup (No Hang Up)

Ejecuta un comando de modo que no reciba la señal HUP (hangup) cuando el usuario se desconecta o cierra la terminal. El proceso continúa ejecutándose en segundo plano.

Sintaxis Descripción
nohup <comando> & Ejecuta el comando en segundo plano (&) e ignora la señal HUP. La salida se redirige al archivo nohup.out

Ejemplo Práctico:

  1. Iniciar un script largo que crea un log y desconectarse inmediatamente sin detenerlo:

nohup ./mi_script_largo.sh &

[1] 12345

nohup: ignoring input and appending output to 'nohup.out'

# Ahora el usuario puede cerrar la sesión de SSH o la terminal, y el script seguirá ejecutándose.

8. rsync (Sincronización Remota)

Una utilidad increíblemente versátil para copiar y sincronizar archivos local y remotamente. Solo transfiere las diferencias, minimizando el ancho de banda.

Opción Común Descripción
rsync -av <origen> <destino> Copia archivos de forma archivada (preservando permisos, etc.) y verbosa (muestra progreso).
rsync -avz <origen> <destino> Añade compresión (-z) durante la transferencia (útil para redes lentas).
rsync --delete Borra archivos en el destino que ya no existen en el origen (sincronización estricta).

Ejemplo Prácticos:

  1. Sincronizar el directorio de documentos de jose con una copia de seguridad en un disco externo (localmente):

rsync -av ~/Documentos/ /mnt/backup_drive/documentos_bkp/

  1. Sincronizar archivos a un servidor remoto a través de SSH (el servidor es servidor01):

jose@Ubuntu2404:~$ rsync -avz --progress ~/logs/ jose@servidor01:/var/backups/

rsync -avz --progress ~/logs/ jose@servidor01:/var/backups/

Parte del Comando Significado Función
rsync Comando principal Utilidad de sincronización eficiente.
-a Archive mode Combina varias opciones esenciales: preserva permisos, propietario, grupo, timestamps, y recursividad. Es crucial para backups.
-v Verbose Muestra una lista de archivos que se están transfiriendo para que sepas qué está sucediendo.
-z Compress Comprime los datos durante la transferencia SSH, lo que acelera el proceso, especialmente con archivos grandes o conexiones lentas.
--progress Progress Muestra el progreso de cada archivo individualmente, dando una indicación visual de la velocidad y el tiempo restante.
~/logs/ Origen (Source) La ruta a la carpeta local que se va a enviar. La barra diagonal final (/) es importante; significa que se sincroniza el contenido de logs/, no la carpeta logs en sí.
jose@servidor01: Conexión SSH Especifica la conexión al servidor remoto (servidor01) usando el usuario jose.
/var/backups/ Destino (Destination) El directorio en el servidor remoto donde se guardará el contenido de la carpeta logs/.

Solo debes asegurar que:

  1. El servidor servidor01 sea accesible por nombre o IP.

  2. El servicio SSH (sshd) esté activo en servidor01 (normalmente en el puerto 22, como hablamos antes).

  3. El usuario jose tenga permisos de escritura en el directorio remoto /var/backups/.

Comandos de Multiplexación de Terminal

screen y tmux (Multiplexores de Terminal)

Ambos son multiplexores de terminal que permiten crear múltiples sesiones de terminal persistentes. Puedes desconectarte (detachar) de una sesión y volver a conectarte (reatachar) más tarde, manteniendo los programas en ejecución. Son esenciales para el trabajo en servidores.

Comando Descripción
screen Inicia una nueva sesión de screen.
screen -ls Lista las sesiones de screen abiertas.
screen -r <pid> Reataquea la sesión especificada.
tmux Inicia una nueva sesión de tmux.
tmux ls Lista las sesiones de tmux abiertas.
tmux attach-session -t <nombre> Reataquea la sesión especificada por nombre.

Ejemplos Prácticos (usando screen como ejemplo):

sudo apt install screen

  1. Iniciar una sesión de screen y ejecutar un comando largo:

screen

# (Ahora estás en la nueva sesión de screen)

ping google.com

  1. Desconectarse (Detachar) de la sesión (sin detener el ping):

    • Presiona Ctrl+A y luego suelta y presiona la tecla D.

    • Verás: [detached from 12345.pts-0.Ubuntu2404]

  2. Volver a la sesión para ver cómo sigue el ping:

screen -r

# El ping sigue ejecutándose donde lo dejaste.

Es muy común que los usuarios de terminal tengan problemas la primera vez que intentan desconectarse (detachar) de una sesión de screen, ya que la secuencia de teclas es específica y no produce una salida inmediata visible.

Debes usar la tecla de comando (Ctrl+A) seguida de la tecla de acción (D).

  1. Inicia screen:

screen

La pantalla se limpiará y verás un prompt normal, pero ahora estás dentro de una sesión de screen.

  1. Ejecuta el Comando Largo:

Ejecuta el comando que quieres que se siga ejecutando en segundo plano:

ping google.com

Verás que el ping comienza a ejecutarse, mostrando una línea de respuesta cada segundo.

Desconectarse (Detachar) de la Sesión

Para que el comando ping siga ejecutándose en el entorno de screen mientras tú vuelves a tu terminal principal, debes presionar la secuencia de teclas de comando:

  1. Presiona y mantén la tecla Ctrl.

  2. Mientras mantienes Ctrl, presiona la tecla A.

  3. Suelta ambas teclas (Ctrl y A).

  4. Inmediatamente, presiona la tecla D (de Detach).

Resultado Esperado

Si lo haces correctamente, dejarás de ver el ping y volverás al prompt de tu terminal principal

Verás un mensaje de confirmación similar a este:

[detached from 12345.pts-0.Ubuntu2404]

Esto confirma que la sesión con el ping sigue activa en el sistema, pero desconectada de tu terminal.

Volver a Conectar (Reattach) a la Sesión

Si deseas ver el estado actual del ping, puedes volver a conectarte a la sesión que dejaste en segundo plano.

  1. Lista las sesiones activas (opcional, pero útil si tienes varias):

screen -ls

Verás algo como There is a screen on: 12345.pts-0.Ubuntu2404 (Detached).

  1. Vuelve a la sesión:

screen -r

Si solo tienes una sesión desconectada, screen -r se conectará automáticamente. Si tienes varias, tendrás que especificar el ID de la sesión (screen -r 12345).

Resultado Esperado

La pantalla se actualizará y verás el ping google.com ejecutándose exactamente donde lo dejaste, con los nuevos paquetes que se enviaron mientras estabas desconectado.
