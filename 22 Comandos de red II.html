Comandos de red

1. Comandos de Diagnóstico y Conectividad

Estos comandos se usan para probar si la red está funcionando y medir el rendimiento.

ping: Prueba de Conectividad (ICMP Echo)

ping (Packet InterNet Groper) es la herramienta fundamental para probar la conectividad a nivel de red (Capa 3). Envía paquetes ICMP Echo Request y espera una respuesta.

Opción Descripción
-c N Limita el número de paquetes a enviar a N.
-i N Intervalo de segundos a esperar entre el envío de cada paquete.

Ejemplo Práctico: Probar la conectividad con un límite

Verificar si hay conexión a Google DNS, pero solo enviando 4 paquetes.

ping -c 4 8.8.8.8

PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.

64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=25.4 ms

64 bytes from 8.8.8.8: icmp_seq=2 ttl=117 time=25.3 ms

64 bytes from 8.8.8.8: icmp_seq=3 ttl=117 time=25.5 ms

64 bytes from 8.8.8.8: icmp_seq=4 ttl=117 time=25.4 ms

--- 8.8.8.8 ping statistics ---

4 packets transmitted, 4 received, 0% packet loss, time 3004ms

El valor Time To Live (TTL) que ves en la respuesta de un ping está directamente relacionado con el sistema operativo (SO) del host de destino y el número de saltos (routers) que el paquete tuvo que recorrer para llegar hasta allí y regresar.

El valor de TTL que recibes en la respuesta no es el TTL inicial del destino, sino el TTL inicial menos los saltos que el paquete realizó.

Valores TTL Iniciales Típicos

El sistema operativo del host de destino es el que establece el valor inicial del TTL. Los valores más comunes que te permiten identificar el SO son:

Sistema Operativo del Destino TTL Inicial Típico
Windows (moderno) 128
Linux/macOS/FreeBSD 64
Sistemas Unix Antiguos (o especializados) 255 (o 64)
Solaris/AIX 254

Cómo Interpretar el TTL de la Respuesta

El TTL que ves en la respuesta de tu ping disminuye en 1 en cada salto (router) que atraviesa el paquete.

TTL de Respuesta=TTL Inicial del Destino−Nuˊmero de Saltos de Retorno

Ejemplo Práctico:

  1. Haces ping a un servidor web que corre en Linux. Su TTL inicial es 64.

  2. El paquete de ida atraviesa 7 routers.

  3. El paquete de respuesta del servidor también atraviesa 7 routers hasta llegar a ti.

TTL Recibido=64−7=57

Si recibes un TTL de 57, sabes que el TTL inicial era 64, lo que sugiere fuertemente que el servidor de destino utiliza un sistema Linux o macOS.

Detección del Sistema Operativo

Puedes estimar el sistema operativo del destino si el TTL recibido en la respuesta está cerca de 64 o 128.

  • Si el TTL de respuesta es, por ejemplo, 120, es casi seguro que el SO es Windows (TTL inicial 128, con 8 saltos de red).

  • Si el TTL de respuesta es, por ejemplo, 59, es casi seguro que el SO es Linux/macOS (TTL inicial 64, con 5 saltos de red).

Si el TTL es muy bajo (ej. 30), el servidor está muy lejos o el paquete ha atravesado muchas redes.

traceroute: Trazar la Ruta de Paquetes

traceroute muestra la ruta (los saltos o hops) que toma un paquete para ir desde el host local hasta el destino, identificando cada router intermedio.

Ejemplo Práctico: Trazar la ruta a un sitio web

sudo apt install traceroute

o

sudo apt install inetutils-traceroute

Quieres ver la ruta que toman sus paquetes hasta el sitio web de Wikipedia.

traceroute wikipedia.org

traceroute to wikipedia.org (208.80.154.224), 30 hops max, 60 byte packets

1 router.local (192.168.1.1) 1.234 ms 1.345 ms 1.456 ms

2 ip-del-isp-de-jose (10.0.0.1) 8.765 ms 9.876 ms 10.987 ms

3 * * *

4 backbone.isp.net (62.xx.xx.xx) 25.123 ms 26.234 ms 27.345 ms

... (Continúa hasta el destino)

El símbolo * * * en la salida del comando traceroute significa que no se recibió ninguna respuesta del router (salto) correspondiente a ese número.

Significado de los * * *

Cada línea de traceroute muestra los resultados de tres pruebas de latencia (tiempo de respuesta) al mismo salto. Si ves * * *, puede deberse a varias razones, siendo las más comunes:

  1. Firewall (Cortafuegos): Es la causa más frecuente. El router en ese salto está configurado con un firewall que bloquea los paquetes ICMP (Internet Control Message Protocol), que son los utilizados por traceroute (y ping) para obtener respuestas. El router recibe el paquete, pero no envía la respuesta de vuelta.

  2. Tráfico Congestionado o Priorización: El router está tan ocupado procesando tráfico de datos prioritario que descarta los paquetes ICMP de traceroute para ahorrar recursos.

  3. Ruta Asimétrica o Pérdida de Paquetes: Los paquetes de respuesta se pierden en el camino de regreso, o el paquete de respuesta toma una ruta completamente diferente y nunca llega a tu máquina.

Que veas * * * no significa necesariamente que tu conexión esté fallando.

Si el traceroute no llega a su destino dentro de los 30 saltos máximos (que es el límite por defecto), verás los asteriscos hasta el final de la lista. En este caso, el servidor de destino es el que está en silencio o la ruta es inalcanzable.

2. Comandos de Información de Red e Interfaces

Estos comandos muestran la configuración de las interfaces de red del host local.

ip: Mostrar/Manipular Enrutamiento, Dispositivos y Túneles (Moderno)

El comando ip es la herramienta moderna y preferida en Linux para configurar interfaces, rutas y túneles.

Comando Función Descripción
ip a address Muestra todas las direcciones IP de todas las interfaces.
ip r route Muestra la tabla de enrutamiento del kernel.
ip link set eth0 up link Activa la interfaz eth0 (requiere sudo).

Ejemplo Práctico: Ver la configuración IP

ip a

1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000

inet 127.0.0.1/8 scope host lo

2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000

inet 192.168.1.50/24 brd 192.168.1.255 scope global dynamic ens33

(Aquí, jose tiene la IP 192.168.1.50 en la interfaz ens33.)

ifconfig: Configuración de Interfaces (Legado)

ifconfig es la herramienta de configuración de red tradicional y ha sido reemplazada por ip en distribuciones modernas, pero sigue siendo útil y común.

Ejemplo Práctico: Ver interfaces (similar a ip a)

3. Comandos de Conexiones de Red y Sockets

Estos comandos listan las conexiones activas, puertos abiertos y sockets.

netstat: Estadísticas de Red (Legado)

netstat (network statistics) es una herramienta antigua para monitorear las conexiones de red.

Opción Descripción
-tulpn Muestra sockets tcp, udp, listening (escuchando), programa/PID, numéricos.
-r Muestra la tabla de rutas (similar a ip r).

Ejemplo Práctico: Ver todos los puertos de escucha y sus programas

netstat -tulpn | grep LISTEN

(Not all processes could be identified, non-owned process info

will not be shown, you would have to be root to see it all.)

tcp 0 0 0.0.0.0:22 0.0.0.0:* LISTEN -

tcp 0 0 127.0.0.53:53 0.0.0.0:* LISTEN -

(Vemos que el puerto 22 (SSH) y el 53 (DNS) están escuchando.)

ss: Estadísticas de Socket (Moderno)

ss es el reemplazo moderno de netstat, mucho más rápido y eficiente.

Opción Descripción
-l Muestra solo los sockets en estado de listening (escucha).
-t Muestra solo los sockets tcp.
-u Muestra solo los sockets udp.
-p Muestra el proceso que usa el socket.
-n Muestra direcciones y puertos numéricos.

Ejemplo Práctico: Listar conexiones TCP establecidas

Quieres ver todas las conexiones TCP que están actualmente establecidas.

ss -t state established

Netid State Recv-Q Send-Q Local Address:Port Peer Address:Port

tcp ESTAB 0 0 192.168.1.50:52345 142.250.203.14:443

tcp ESTAB 0 0 192.168.1.50:48912 172.67.158.42:80

nslookup es una herramienta antigua y sencilla para realizar consultas DNS.

Opción Descripción

TIPO Especifica el tipo de registro (ej. MX para registros de correo, NS para servidores de nombres).

Checklist – Fase de Mapeo de Red

Identificar interfaces y configuración de red

Antes de escanear, confirma tu IP, máscara y gateway.

ip a

ip route

hostname -I

ifconfig        # (alternativa clásica)

Comprobar conectividad básica

ping -c 4 192.168.1.1        # Ping a un host concreto

ping -b 192.168.1.255        # Ping broadcast (si está permitido)

Descubrimiento de hosts en la red local

ARP Scan

sudo arp-scan -l

sudo arp-scan 192.168.1.0/24

sudo arp-scan -I eth0 -g 192.168.1.0/24

Comando Alcance del Escaneo Interfaz de Red Nivel de Especificación
arp-scan -l Escanea la red local (la subred de la interfaz configurada por defecto). Automático (usa la interfaz por defecto). Mínimo (rápido para redes simples).
sudo arp-scan 192.168.1.0/24 Escanea el rango de red especificado (192.168.1.0/24). Automático (usa la interfaz por defecto). Medio (requiere especificar la red).
sudo arp-scan -I eth0 -g 192.168.1.0/24 Escanea el rango especificado, usando una interfaz y dirección IP de origen definidas. Específico (eth0). Máximo (requiere especificar interfaz y rango).

1. arp-scan -l (Local Subnet Scan)

  • -l significa "local" o "localnet".

  • Este es el método más simple y rápido. arp-scan detecta automáticamente qué interfaz de red estás usando (por ejemplo, eth0 o enp0s3) y cuál es la dirección IP y la máscara de subred asignadas a esa interfaz (por ejemplo, 192.168.1.100/24).

  • Luego, escanea toda esa subred local completa.

Uso: Ideal para una comprobación rápida de los dispositivos conectados a la misma red física que tu máquina, sin necesidad de conocer la configuración IP.

2. sudo arp-scan 192.168.1.0/24 (Specified Network Scan)

  • Aquí, le estás diciendo explícitamente a arp-scan qué rango de red debe escanear (192.168.1.0 con una máscara de /24).

  • Aunque especificas el rango, el comando sigue usando la interfaz de red por defecto que el sistema operativo ha elegido para alcanzar esa red.

  • Requiere sudo si el rango especificado no coincide con la red a la que está conectada tu interfaz por defecto.

Uso: Útil cuando quieres escanear una red diferente a la que estás conectado directamente, o si quieres limitar el escaneo a un rango específico dentro de tu propia subred.

3. sudo arp-scan -I eth0 -g 192.168.1.0/24 (Interface and Gateway Scan)

  • -I eth0 (Interface): Le dice a arp-scan que debe usar exclusivamente la interfaz de red eth0 para enviar los paquetes ARP. Esto es crucial en sistemas con múltiples interfaces de red.

  • -g 192.168.1.0/24 (Generate): En este caso, la bandera -g se utiliza para especificar el rango de red que se va a escanear (el comando arp-scan en versiones recientes usa la notación CIDR directamente, por lo que a menudo se usa como sinónimo de especificar el rango, aunque históricamente significaba usar la dirección del gateway).

Uso: Es el método más preciso y explícito. Se utiliza cuando necesitas controlar exactamente qué interfaz envía los paquetes ARP o cuando quieres simular un escaneo desde una dirección IP de origen específica. Siempre requiere sudo porque manipular interfaces de red y enviar paquetes ARP de bajo nivel necesita privilegios de superusuario.

Netdiscover

sudo netdiscover -r 192.168.1.0/24

sudo netdiscover -i eth0 -r 192.168.1.0/24

Ambos comandos realizan un escaneo pasivo/activo en el rango de red (-r 192.168.1.0/24), pero solo el segundo garantiza que el escaneo se realice a través de una interfaz específica.

1. sudo netdiscover -r 192.168.1.0/24

  • -r 192.168.1.0/24: Indica el rango de red completo a escanear (en notación CIDR). netdiscover intentará escanear todas las IP desde 192.168.1.0 hasta 192.168.1.255.

  • Interfaz: El programa elige la interfaz de red por defecto que el sistema operativo ha configurado para el tráfico de salida. En un sistema con una sola tarjeta de red, esto suele ser eth0 o similar, pero en sistemas con múltiples interfaces (como Wi-Fi y Ethernet, o múltiples tarjetas virtuales), la elección puede ser ambigua o incorrecta.

2. sudo netdiscover -i eth0 -r 192.168.1.0/24

  • -i eth0: Esta es la diferencia clave. La bandera -i (interface) obliga a netdiscover a utilizar la interfaz eth0 para enviar y recibir todos los paquetes de escaneo.

  • -r 192.168.1.0/24: Mantiene el mismo rango de red a escanear.

La diferencia se reduce a control y precisión:

  • Primer Comando (Sin -i): Se basa en la configuración por defecto del sistema. Es más fácil de usar pero menos preciso en entornos de red complejos.

  • Segundo Comando (Con -i eth0): Ofrece mayor control. Es necesario si tienes múltiples interfaces de red y quieres asegurarte de que el escaneo se realiza a través de la interfaz que está conectada a la red 192.168.1.x.

En resumen: Siempre es una buena práctica utilizar -i para especificar la interfaz, ya que elimina ambigüedades y garantiza que los paquetes de escaneo ARP/DHCP se envíen a través del segmento de red correcto.

Fping (ping masivo)

fping -a -g 192.168.1.0/24 2>/dev/null

fping -I eth0 -g 192.168.1.0/24 -a 2>/dev/null

Ambos comandos fping tienen el mismo objetivo: escanear el rango de red 192.168.1.0/24 en busca de hosts activos, mostrando solo los que responden (-a). La diferencia principal, al igual que con arp-scan y netdiscover, es la especificación de la interfaz de red.

Característica fping -a -g 192.168.1.0/24 2>/dev/null fping -I eth0 -g 192.168.1.0/24 -a 2>/dev/null
Interfaz (-I) Automática (Utiliza la interfaz de red por defecto). Específica (-I eth0). Fuerza el uso de la interfaz eth0.
Rango (-g) Explícitamente definido (192.168.1.0/24). Explícitamente definido (192.168.1.0/24).
Salida (-a) Muestra solo los hosts activos (-a). Muestra solo los hosts activos (-a).
Redirección (2>/dev/null) Oculta la salida de errores (E/S Estándar de Error). Oculta la salida de errores (E/S Estándar de Error).

1. fping -a -g 192.168.1.0/24 2>/dev/null

Este comando se basa en la configuración de red por defecto de tu sistema. El sistema operativo decidirá qué interfaz usar para enviar los paquetes ICMP Echo Request (ping).

  • Es el método más sencillo y funcional si solo tienes una interfaz de red o si la interfaz correcta es la predeterminada del sistema.

2. fping -I eth0 -g 192.168.1.0/24 -a 2>/dev/null

El uso de la opción -I eth0 (Interface) es la diferencia crucial.

  • Esta opción fuerza a fping a vincular los paquetes ICMP exclusivamente a la interfaz eth0.

  • Es esencial en sistemas con múltiples interfaces de red (como tu VirtualBox, que podría tener eth0 y una interfaz de loopback, o más) para garantizar que el escaneo de la subred se origine desde la interfaz correcta que está conectada a la red 192.168.1.x.

En resumen: Si solo tienes una interfaz de red relevante, los resultados serán idénticos. Si tienes varias interfaces, el segundo comando es más fiable porque elimina cualquier ambigüedad sobre qué interfaz debe usarse para el escaneo.

Nmap

Nmap – Ping Sweep

sudo nmap -sn 192.168.1.0/24

Escaneo de puertos y servicios

Nmap – Puertos comunes

sudo nmap -T4 -F 192.168.1.0/24

La diferencia principal entre estos dos comandos Nmap es su propósito y profundidad del escaneo: el primero realiza solo un "Ping Sweep" (detección de hosts) para saber qué direcciones IP están activas, mientras que el segundo realiza un escaneo de puertos más rápido y detallado en esos hosts activos.

1. sudo nmap -sn 192.168.1.0/24 (Ping Sweep / Detección de Hosts)

Este comando tiene como único objetivo identificar qué hosts (dispositivos) están activos en el rango de red especificado (192.168.1.0/24).

  • -sn (Scan No port): Es la abreviatura de "Ping Scan" (antes era -sP). Le indica a Nmap que no realice escaneos de puertos (TCP/UDP).

  • Función: Envía peticiones ARP, ICMP (ping), y paquetes TCP/UDP a los hosts del rango para determinar si están encendidos y conectados a la red.

  • Resultado: Solo te mostrará una lista de las direcciones IP que respondieron, pero no te dirá qué servicios o puertos tienen abiertos.

  • Velocidad: Es un escaneo muy rápido.

2. sudo nmap -T4 -F 192.168.1.0/24 (Escaneo Rápido de Puertos y Servicios)

Este comando es un escaneo de puertos y servicios con opciones de velocidad y enfoque. Asume que se ha realizado una detección de hosts y procede a examinar los puertos.

  • -T4 (Tiempo Agresivo): Le indica a Nmap que use un nivel de temporización 4. Esto acelera el escaneo para que se ejecute más rápido, aunque puede ser ligeramente más ruidoso o menos preciso en redes lentas.

  • -F (Fast mode): Le indica a Nmap que escanee solo los 100 puertos TCP más comunes (o "populares"), en lugar de los 1000 puertos por defecto. Esto reduce drásticamente el tiempo de escaneo.

  • Función: Una vez que un host es detectado, Nmap intenta establecer una conexión con los puertos TCP más comunes para determinar si están abiertos, cerrados o filtrados.

  • Resultado: Muestra la dirección IP, el estado de los puertos (por ejemplo, 80/tcp abierto), y generalmente intenta identificar el servicio que se está ejecutando en ese puerto (por ejemplo, HTTP).

  • Velocidad: Es un escaneo moderadamente rápido (gracias a -T4 y -F), mucho más lento que el "Ping Sweep" pero mucho más rápido que un escaneo de 65535 puertos.

nmap -T4 -F Descubrir servicios (¿Qué está abierto?). Escaneo Rápido de Puertos. SÍ

Masscan (muy veloz, cuidado con el rate)

sudo masscan 192.168.1.0/24 -p1-65535 --rate=1000

Masscan es conocida por su capacidad de escanear la Internet completa en minutos, por lo que es extremadamente rápido incluso en redes locales.

Parte del Comando Significado Explicación
sudo masscan Ejecutar Masscan con privilegios de root. Masscan requiere privilegios elevados (sudo) para enviar paquetes RAW (crudos) a alta velocidad.
192.168.1.0/24 Rango objetivo (Target). Especifica la subred completa de clase C (256 direcciones IP, de 192.168.1.1 a 192.168.1.254) que se va a escanear.
-p1-65535 Rango de puertos. Indica que se escanearán todos los 65.535 puertos TCP posibles en cada una de las direcciones IP del rango especificado.
--rate=1000 Velocidad de escaneo. Limita la velocidad de escaneo a 1000 paquetes por segundo.

Este comando está diseñado para realizar un escaneo de puertos exhaustivo (-p1-65535) a una velocidad controlada (--rate=1000) en toda la red local.

  1. Escaneo de Puertos Completo: Al escanear todos los 65.535 puertos, te aseguras de no perderte ningún servicio inusual que se ejecute en un puerto no estándar.

  2. Velocidad Controlada: La opción --rate=1000 se utiliza para evitar saturar la red local o que los sistemas de detección de intrusiones (IDS/IPS) te detecten inmediatamente. 1000 paquetes por segundo es relativamente rápido, pero aún permite que el sistema responda sin sobrecargarse.

  3. Resultados: La salida mostrará una lista de las direcciones IP y los números de puerto en esa subred que están detectados como abiertos.

Unicornscan

sudo unicornscan -Iv 192.168.1.0/24:a

Unicornscan, que es un escáner de red asíncrono diseñado para ser muy rápido y flexible.

Parte del Comando Significado Explicación
unicornscan La herramienta de escaneo. Unicornscan es conocido por su alta velocidad, ya que utiliza métodos de escaneo asíncronos y sin estado (stateless) para procesar paquetes.
-Iv Opciones de verbosidad (Verbose). -I (o -i) significa "informational" (informativo) y -v significa "verbose" (verboso). Estas opciones combinadas indican a Unicornscan que muestre información detallada (y a menudo más ruidosa) sobre el proceso y los resultados del escaneo.
192.168.1.0/24:a Target y Modo de Escaneo. Esta es la parte más crucial y específica de Unicornscan:
192.168.1.0/24 Especifica la subred completa de Clase C (256 direcciones IP) como el objetivo del escaneo.
:a Es el rango de puertos o el modo de escaneo. El sufijo :a es un atajo que indica a Unicornscan que escanee todos los puertos TCP (1-65535) en cada dirección IP del rango.

Propósito del Escaneo

El objetivo de este comando es realizar un escaneo completo y rápido de todos los puertos TCP en todas las máquinas de la subred 192.168.1.0/24, mostrando una salida detallada del proceso.

  • Alcance: Escanea las 254 direcciones IP utilizables en el rango.

  • Profundidad: Escanea 65.535 puertos por cada IP (es decir, un escaneo de puertos completo).

  • Resultado: La salida mostrará una lista de los puertos detectados como abiertos o cerrados en cada host activo dentro de la red.
