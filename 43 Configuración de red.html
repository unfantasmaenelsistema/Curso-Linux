Guía: Configuración de red en Linux

1) Conceptos clave

  • IP fija (estática) → una dirección manual para un equipo (ej. servidor).

  • DHCP → asigna IPs dinámicamente a clientes.

  • DNS → traduce nombres de dominio a IPs.

  • dnsmasq → servicio ligero que combina DHCP + DNS local.

  • nmap / tcpdump → herramientas para analizar y diagnosticar la red.

2) Asignar IP fija

En distribuciones modernas (con Netplan – Ubuntu/Debian 18+)

Archivo: /etc/netplan/01-netcfg.yaml
Ejemplo de configuración estática:

network:

version: 2

ethernets:

ens33:

dhcp4: no

addresses:

- 192.168.1.50/24

gateway4: 192.168.1.1

nameservers:

addresses: [8.8.8.8, 1.1.1.1]

Aplicar cambios:

sudo netplan apply

En distribuciones con ifconfig/interfaces (clásico Debian/Ubuntu < 18)

Archivo: /etc/network/interfaces

auto eth0

iface eth0 inet static

address 192.168.1.50

netmask 255.255.255.0

gateway 192.168.1.1

dns-nameservers 8.8.8.8 1.1.1.1

Reiniciar red:

sudo systemctl restart networking

Ejercicio 1

  1. Configura tu tarjeta en 192.168.56.20/24 (en una red virtual).

  2. Haz ping 192.168.56.1 (la puerta de enlace de VirtualBox/VMware).

  3. Comprueba con ip a que la IP se aplicó.

3) Montar un servidor DHCP/DNS local con dnsmasq

Instalación

sudo apt install dnsmasq # Debian/Ubuntu

sudo dnf install dnsmasq # RHEL/CentOS

Configuración básica de DHCP

Editar /etc/dnsmasq.conf:

# interfaz de red a usar

interface=eth0

# rango de IPs a entregar (pool DHCP)

dhcp-range=192.168.1.100,192.168.1.150,12h

Reiniciar servicio:

sudo systemctl restart dnsmasq

sudo systemctl enable dnsmasq

Configuración básica de DNS local

En /etc/dnsmasq.conf agrega:

# asignar IP fija por hostname

address=/intranet.local/192.168.1.50

Esto hace que ping intranet.local resuelva a 192.168.1.50.

Ejercicio 2

  1. Configura un rango DHCP 192.168.56.100 – 192.168.56.120.

  2. En otra VM cliente, pon la red en modo DHCP y comprueba con ip a qué IP recibió.

  3. Añade un DNS local:

  4. address=/curso.local/192.168.56.20

Luego desde el cliente, prueba ping curso.local.

4) Análisis de red con nmap

Instalación

sudo apt install nmap

Escaneos básicos

nmap 192.168.1.1 # detecta puertos abiertos en 1 host

nmap 192.168.1.0/24 # escanea toda la subred

nmap -sV 192.168.1.10 # detecta versiones de servicios

nmap -O 192.168.1.10 # intenta identificar el SO

Ejercicio 3

  1. Escanea tu propia red nmap 192.168.56.0/24.

  2. Identifica al menos un host con un puerto abierto (ej. 22 o 80).

  3. Explica qué servicio corresponde a ese puerto.

5) Análisis de red con tcpdump

Instalación

sudo apt install tcpdump

Capturas básicas

sudo tcpdump -i eth0 # captura tráfico en la interfaz eth0

sudo tcpdump -i eth0 port 80 # solo tráfico HTTP

sudo tcpdump -i eth0 host 192.168.1.50 # tráfico hacia/desde un host

sudo tcpdump -w captura.pcap # guarda captura en archivo para Wireshark

Ejemplo en clase

En una terminal:

ping 8.8.8.8

En otra:

sudo tcpdump -i eth0 icmp

→ Verás los paquetes ICMP echo request/reply.

Ejercicio 4

  1. Lanza un ping google.com.

  2. Usa tcpdump -i eth0 icmp para capturar.

  3. Explica la diferencia entre echo request y echo reply.

6) Ejercicio integrador

Escenario: Debes configurar un pequeño laboratorio de red.

  • El servidor (VM1) tendrá IP fija 192.168.56.10.

  • El servidor correrá dnsmasq entregando IPs entre 192.168.56.100-120.

  • Un cliente (VM2) debe obtener IP automáticamente y resolver el nombre servidor.local al 192.168.56.10.

  • Luego, analiza desde VM2 con nmap qué puertos están abiertos en 192.168.56.10.

Resultado esperado:

  • Cliente recibe IP en rango.

  • ping servidor.local funciona.

  • nmap 192.168.56.10 muestra puertos abiertos (ej. 22 para SSH).

7) Cheatsheet rápido

# redes

ip a

ping 8.8.8.8

ip route show

# configurar IP temporal

sudo ip addr add 192.168.1.50/24 dev eth0

sudo ip route add default via 192.168.1.1

# netplan (Ubuntu moderno)

sudo nano /etc/netplan/*.yaml

sudo netplan apply

# dnsmasq

sudo apt install dnsmasq

sudo nano /etc/dnsmasq.conf

sudo systemctl restart dnsmasq

# nmap

nmap -sV 192.168.1.10

nmap 192.168.1.0/24

# tcpdump

sudo tcpdump -i eth0 port 80

sudo tcpdump -w salida.pcap
