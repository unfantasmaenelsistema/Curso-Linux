route - Mostrar/Modificar la Tabla de Enrutamiento

El comando route (aunque obsoleto y reemplazado por ip route, sigue siendo funcional) se utiliza para ver y manipular las entradas en la tabla de enrutamiento del núcleo. Esta tabla determina por dónde deben enviarse los paquetes de red para llegar a diferentes destinos.

Opciones Comunes

Opción Descripción
-n Muestra direcciones y números de puerto numéricamente (evita la resolución de nombres DNS, haciendo que la salida sea más rápida).
add Agrega una ruta a la tabla.
del Elimina una ruta de la tabla.
default Se refiere a la puerta de enlace (gateway) por defecto.

Ejemplos Prácticos

  1. Ver la tabla de enrutamiento del sistema (numéricamente):

Este es el uso más común y te muestra las redes conectadas directamente y la puerta de enlace predeterminada.

route -n

Salida esperada:

Kernel IP routing table

Destination Gateway Genmask Flags Metric Ref Use Iface

0.0.0.0 192.168.1.1 0.0.0.0 UG 100 0 0 ens33 <- Ruta por defecto (Gateway)

192.168.1.0 0.0.0.0 255.255.255.0 U 100 0 0 ens33 <- Red local

  1. Agregar una ruta estática (requiere sudo):

Imagina que la red 172.16.0.0/16 solo es accesible a través de un router específico con la IP 192.168.1.254.

sudo route add -net 172.16.0.0 netmask 255.255.0.0 gw 192.168.1.254 dev ens33

Parte del Comando Explicación
route Es la utilidad de red utilizada para mostrar o manipular la tabla de enrutamiento IP (kernel) del sistema.
add Es una opción del comando route que indica que se va a añadir una nueva ruta a la tabla.
-net 172.16.0.0 Especifica la red de destino. En este caso, la ruta se aplicará a todo el tráfico destinado a la red IP 172.16.0.0.
netmask 255.255.0.0 Define la máscara de subred para la red de destino. Una máscara de 255.255.0.0 indica que los primeros 16 bits de la dirección IP (los dos primeros octetos) identifican la red, lo que significa que la red es 172.16.0.0/16 (una subred de clase B).
gw 192.168.1.254 Significa "gateway" (puerta de enlace). Especifica la dirección IP del router o el siguiente salto al que se debe enviar el tráfico destinado a la red 172.16.0.0/16. El tráfico se enviará a la IP 192.168.1.254.
dev ens33 Indica la interfaz de red local que el sistema debe utilizar para alcanzar la puerta de enlace (192.168.1.254). ens33 es el nombre de la interfaz de red (por ejemplo, una tarjeta de red virtual o física) del sistema que ejecuta el comando.

El propósito del comando es:

"Para alcanzar cualquier dirección dentro de la red 172.16.0.0 con máscara de subred 255.255.0.0 (es decir, la red 172.16.x.x), envía los paquetes al router cuya dirección IP es 192.168.1.254, utilizando la interfaz de red local llamada ens33."

Nota Importante:

Esta ruta agregada con el comando route (o la herramienta más moderna ip route) es temporal y se perderá al reiniciar el sistema. Para hacer la ruta persistente, se requerirían modificaciones en archivos de configuración específicos del sistema operativo (por ejemplo, /etc/network/interfaces en Debian/Ubuntu antiguos, o usar netplan, NetworkManager o archivos de configuración de ruta en /etc/sysconfig/network-scripts/ en sistemas basados en Red Hat).

  1. Eliminar la ruta que acabas de crear (requiere sudo):

sudo route del -net 172.16.0.0 netmask 255.255.0.0

arp - Ver la Caché ARP

El Protocolo de Resolución de Direcciones (ARP) mapea direcciones IP (Capa 3) a direcciones físicas MAC (Capa 2) dentro de una red local. El comando arp te permite inspeccionar y manipular la caché ARP del sistema.

Opciones Comunes

Opción Descripción
-a Muestra todas las entradas en la caché ARP (el uso más común).
-d Elimina una entrada específica.
-i <interfaz> Muestra entradas solo para la interfaz especificada.

Ejemplos Prácticos

  1. Mostrar todas las entradas en la caché ARP:

Esto te mostrará la IP y la dirección MAC de los dispositivos con los que te has comunicado recientemente en tu red local (como el router o el servidor DNS).

arp -a

Salida esperada:

? (192.168.1.1) at 00:50:56:ff:ff:ff [ether] on ens33 <- Router/Gateway

? (192.168.1.5) at 08:00:27:01:02:03 [ether] on ens33

  1. Eliminar una entrada específica de la caché ARP (requiere sudo):

Útil para diagnosticar problemas o forzar una nueva resolución ARP.

sudo arp -d 192.168.1.5

tcpdump - Capturar Tráfico de Red

tcpdump es un potente analizador de paquetes de línea de comandos. Se utiliza para capturar, filtrar y examinar los paquetes que viajan a través de una interfaz de red.

sudo apt install tcpdump

Opciones Comunes

Opción Descripción
-i <interfaz> Escucha paquetes en la interfaz especificada (ej. ens33 o lo).
-n No resuelve nombres DNS (muestra IPs numéricas).
-c <N> Detiene la captura después de capturar N paquetes.
-w <archivo> Escribe los paquetes capturados en un archivo para analizarlos posteriormente (formato .pcap).

Ejemplos Prácticos

  1. Capturar 5 paquetes en la interfaz de red principal (ens33) sin resolver nombres (requiere sudo):

sudo tcpdump -i ens33 -n -c 5

  1. Capturar solo el tráfico HTTP (puerto 80) y guardarlo en un archivo:

Útil para auditorías o análisis específicos.

sudo tcpdump -i ens33 port 80 -w http_traffic.pcap

Después de capturar algunos paquetes, presiona Ctrl+C para detener la captura.

1. Comprobar Interfaces y Modo Básico

Antes de empezar, necesitas saber qué interfaces de red están disponibles.

1.1. Listar interfaces disponibles

sudo tcpdump -D

Explicación: La opción -D (Display) te muestra las interfaces de red disponibles (eth0, wlan0, lo para loopback, o any para todas). Una vez que sepas el nombre de tu interfaz principal (ej. eth0, ens33 o similar), lo usarás en los siguientes comandos. Si no estás seguro, usa any.

1.2. Captura básica en tiempo real

sudo tcpdump -i any

Explicación: Captura todo el tráfico que pasa por cualquier interfaz (-i any) y lo muestra en la terminal. Presiona Ctrl+C para detener la captura.

2. Generar Archivos de Captura para Inspección

La práctica más útil es guardar la captura en un archivo con extensión .pcap para poder analizarlo más tarde con herramientas como Wireshark o con el mismo tcpdump.

2.1. Guardar los primeros 100 paquetes

# Reemplaza 'eth0' con tu interfaz si es necesario.

sudo tcpdump -i eth0 -c 100 -w mi_captura.pcap

Explicación:

  • -i eth0: Especifica la interfaz.

  • -c 100: Captura solo los primeros 100 paquetes y se detiene automáticamente.

  • -w mi_captura.pcap: Guarda el tráfico capturado en el archivo mi_captura.pcap.

2.2. Captura de tráfico de navegación web (HTTP/HTTPS)

Este es un ejemplo muy común y útil.

# Captura en cualquier interfaz, guardando en un archivo

sudo tcpdump -i any 'port 80 or port 443' -w trafico_web.pcap

Explicación:

  • 'port 80 or port 443': Es el filtro que limita la captura solo a los puertos 80 (HTTP) y 443 (HTTPS).

  • Mientras el comando esté corriendo, abre un navegador y visita algunas páginas web.

3. Filtrar Capturas por Destino y Protocolo

Estos ejemplos te ayudan a aislar el tráfico relevante.

3.1. Capturar tráfico dirigido a una IP específica

Puedes usar una IP externa (ej. un sitio web) o una interna (ej. otro equipo en tu red).

# Captura 50 paquetes destinados a Google DNS (8.8.8.8) en la interfaz eth0

sudo tcpdump -i eth0 -c 50 dst host 8.8.8.8 -w dns_google.pcap

  • El comando está esperando 50 paquetes que coincidan con el filtro dst host 8.8.8.8 (tráfico con destino a Google DNS).

  • Si tu sistema está haciendo peticiones DNS activamente (por ejemplo, estás navegando o haciendo un ping), puede que los 50 paquetes se capturen en cuestión de segundos.

  • Si tu sistema está inactivo, puede tardar más, incluso minutos, hasta que se generen esos 50 paquetes de tráfico DNS.

  • Si tu sistema está usando un servidor DNS diferente (por ejemplo, el de tu proveedor de internet o uno local), es posible que la captura tarde mucho en llegar a 50, o incluso que no lo haga nunca, si no hay tráfico dirigido a 8.8.8.8.

Cómo comprobarlo y acelerarlo

Para garantizar que el comando termine rápidamente, puedes forzar el tráfico:

  1. Deja el comando tcpdump ejecutándose en una terminal.

  2. Abre una segunda terminal (o sal de la sesión remota y vuelve a conectarte si estás por SSH) y ejecuta:

ping -c 50 8.8.8.8

Esto generará 50 paquetes de tráfico ICMP dirigidos a 8.8.8.8, lo cual debería ser suficiente para que el tcpdump complete su cuenta y termine casi de inmediato.

3.2. Capturar tráfico de un protocolo específico (DNS)

El protocolo DNS usa el puerto 53 y es útil para ver peticiones de resolución de nombres.

sudo tcpdump -i any udp port 53 -w peticiones_dns.pcap

Explicación: El tráfico DNS se realiza principalmente a través del protocolo UDP en el puerto 53. Mientras este comando se ejecuta, puedes probar un ping google.com para generar tráfico DNS.

4. Inspeccionar un Archivo de Captura Existente

Una vez que tienes tu archivo .pcap, puedes revisarlo sin necesidad de Wireshark.

4.1. Leer el archivo y mostrar solo las cabeceras IP

tcpdump -r mi_captura.pcap

Explicación: La opción -r (read) lee el archivo. Mostrará la información básica de cada paquete capturado.

4.2. Mostrar más detalles y evitar la resolución de nombres

Para una inspección más detallada de las direcciones IP y puertos sin que tcpdump intente resolver nombres (lo cual a veces es lento):

tcpdump -nnvvS -r mi_captura.pcap

Explicación:

  • -n: No resuelve direcciones IP a nombres de host.

  • -nn: No resuelve direcciones IP ni números de puerto a nombres de servicio (muestra 80 en lugar de http).

  • -vv: Aumenta el nivel de verbosidad (más detalles).

  • -S: Muestra los números de secuencia TCP absolutos.

¿Qué significa "who-has"?

En el contexto de ARP, la frase who-has (quién tiene) se refiere a una petición o solicitud ARP (ARP Request).

Su significado es:

"Quiero saber la dirección MAC (Media Access Control) asociada a esta dirección IP."

Desglose del Paquete ARP

03:18:39.774904 ARP, Ethernet (len 6), IPv4 (len 4), Request who-has 192.168.1.201 tell 192.168.1.1, length 46

  1. ARP, ... Request: Confirma que es un mensaje de Solicitud del protocolo ARP.

  2. who-has 192.168.1.201: Es la pregunta central. El dispositivo que envía este mensaje está preguntando: "¿Quién tiene la dirección IP 192.168.1.201?" (y, por lo tanto, ¿cuál es su dirección MAC?).

  3. tell 192.168.1.1: Esto indica quién está haciendo la pregunta (el remitente). En este caso, el dispositivo con la IP 192.168.1.1 (que muy probablemente es el router o gateway local) está buscando la dirección MAC de ese otro host.

En resumen, estos paquetes representan una actividad normal de la red donde el router está intentando descubrir las direcciones MAC de los hosts con las IPs .201, .202, y .203 para poder enviarles tráfico a nivel de enlace (Capa 2).

ARP: ¿Por qué es necesario?

ARP es vital porque los datos viajan por la red en dos niveles clave:

  1. Nivel 3 (IP): Para enrutar el tráfico a través de diferentes redes (Internet).

  2. Nivel 2 (MAC/Ethernet): Para entregar el tráfico dentro de la red local (LAN).

Cuando un dispositivo quiere enviar datos a otro host en la misma red local, solo conoce su dirección IP. Necesita usar ARP para traducir esa dirección IP a su correspondiente dirección MAC antes de que el tráfico pueda ser realmente transmitido a través del cable o Wi-Fi.

Conclusión

El dispositivo 192.168.1.1 está enviando peticiones ARP repetidas para las IPs .201, .202, y .203. Esto podría indicar:

  • Actividad normal: El router está construyendo o actualizando su caché ARP.

  • Hosts inactivos: El router está intentando contactar a esos hosts, pero no están respondiendo (no están conectados, están apagados o están configurados con una IP diferente).

  • Escaneo/Broadcast: Podría ser el router o un host escaneando activamente la red para ver qué dispositivos están presentes.

Diferencia entre tcpdump y tshark

En esencia:

  • tcpdump es una herramienta de captura de paquetes ligera y nativa de muchos sistemas Unix, que usa el Filtro de Paquetes de Berkeley (BPF).

  • tshark es la versión de línea de comandos del popular analizador de protocolos Wireshark, ofreciendo un análisis mucho más profundo y avanzado, y usa filtros de visualización (Display Filters) al estilo Wireshark.

Comparativa Detallada

Característica tcpdump tshark
Origen Herramienta original, nativa de UNIX. Componente de la suite de software Wireshark.
Análisis Básico. Captura y muestra paquetes sin un análisis profundo de protocolos (a menos que se use la opción -v o similar). Avanzado. Utiliza los mismos dissectores de protocolos que Wireshark, permitiendo un análisis detallado de la capa de aplicación.
Interfaz Línea de comandos (CLI). Diseñado para ser muy ligero y rápido. Línea de comandos (CLI). Más robusto y con más opciones que tcpdump.
Filtros de Captura Utiliza la sintaxis de Filtros de Paquetes de Berkeley (BPF) (ej: port 80, host 192.168.1.1). Utiliza sintaxis BPF para la captura.
Filtros de Análisis/Visualización No tiene un sistema de filtros de visualización dedicados; el análisis se hace con comandos externos (grep, awk). Utiliza la sintaxis avanzada de Filtros de Visualización de Wireshark (ej: http.request, ip.addr == 192.168.1.1).
Uso Típico Capturas rápidas, debugging inicial, análisis en servidores remotos (sin GUI), uso en scripts automatizados por su ligereza. Análisis detallado de un protocolo específico, exportación de datos, uso de las amplias funcionalidades de Wireshark sin la interfaz gráfica.
Requisitos Muy ligero. Suele estar preinstalado o es fácil de instalar. Generalmente requiere la instalación de la suite Wireshark (o al menos sus componentes principales), lo que lo hace más pesado.

¿Cuándo usar cada uno?

Usa tcpdump cuando:

  1. Necesitas ligereza: Estás en un servidor con recursos limitados o donde la instalación de Wireshark/TShark es difícil o innecesaria.

  2. Solo necesitas la información esencial: Quieres verificar rápidamente si el tráfico llega (ej: pings, peticiones TCP/UDP).

  3. Estás en un entorno minimalista: Trabajas en un servidor sin interfaz gráfica (GUI) y quieres una herramienta de captura mínima.

  4. Quieres un alto rendimiento: Necesitas capturar un gran volumen de tráfico con la menor sobrecarga posible.

Usa tshark cuando:

  1. Necesitas análisis de protocolo profundo: Quieres diseccionar el tráfico en las capas de aplicación (HTTP, DNS, SIP, etc.) para ver la estructura exacta del paquete.

  2. Quieres usar filtros complejos de Wireshark: Necesitas filtrar paquetes basándote en campos de protocolo específicos (ej: mostrar solo respuestas DNS que fallaron, o solo encabezados HTTP específicos).

  3. Buscas integración con Wireshark: Quieres capturar el tráfico en un servidor (con tshark) y luego transferir el archivo de captura (.pcap) a tu PC para analizarlo cómodamente con la interfaz gráfica de Wireshark.

  4. Necesitas exportar datos: Quieres exportar campos específicos de paquetes a un formato legible por máquina (CSV, JSON).

whois - Consulta de Dominios y Redes

El comando whois consulta bases de datos públicas para obtener información de registro sobre un nombre de dominio o una dirección IP. Te proporciona detalles sobre el registrante, el administrador, las fechas de creación/expiración y los servidores de nombres.

Ejemplos Prácticos

  1. Consultar la información de registro de un dominio:

whois adidas.es

─$ whois adidas.es

This TLD has no whois server, but you can access the whois database at https://www.dominios.es/en

La herramienta whois en tu sistema no sabe directamente cómo consultar la información para los dominios que terminan en .es (el TLD de España).

En lugar de usar un servidor WHOIS estándar como lo haría con un dominio .com o .org, el registrador oficial de dominios .es requiere que la consulta se haga a través de su propia plataforma web.

Solución: Cómo Consultar el WHOIS para .es

Para obtener la información WHOIS del dominio adidas.es, tienes dos opciones:

Opción 1: Usar la web oficial (Recomendado)

Debes visitar el enlace que el mismo mensaje te proporcionó y realizar la búsqueda allí:

  1. Abre un navegador web en tu máquina Kali.

  2. Ve a la dirección: https://www.dominios.es/en

  3. Ingresa adidas.es en la barra de búsqueda WHOIS.

Opción 2: Forzar la consulta a un servidor específico

Algunas versiones de whois te permiten especificar manualmente el servidor que debe consultar. El servidor oficial para los dominios .es a veces es whois.nic.es.

Puedes intentar el siguiente comando en tu terminal de Kali, aunque no siempre funciona si el servidor requiere un formato de consulta específico:

whois -h whois.nic.es adidas.es

Si esto funciona, obtendrás directamente en la terminal los datos del registrante, las fechas de registro y expiración, y los servidores DNS de adidas.es.

Nota: Es común que los registros de dominios de código de país (ccTLD) como .es, .uk o .de tengan servidores WHOIS personalizados o incluso solo permitan la consulta a través de su sitio web por motivos de política local.

La forma más fácil de probar el comando whois para dominios .com o .org es usar sitios web de alta visibilidad, ya que su información WHOIS es pública y está alojada en servidores estándar:

whois wikipedia.org

Salida:

  • Información del registrante, que será la Wikimedia Foundation, Inc.

  • El ID del registrador y la URL de contacto.

  • Los datos de contacto (aunque a menudo están ofuscados o usan servicios de privacidad).

  1. Consultar información sobre un bloque de direcciones IP:

Esto te mostrará a qué Organización Regional de Registro de Internet (RIR) pertenece el bloque IP, quién lo administra y su rango.

whois 8.8.8.8

Salida (fragmento): Mostrará que la IP 8.8.8.8 pertenece a Google LLC.

whois google.com

  • La Registrant Organization (organización registrante, probablemente Google LLC).

  • Las fechas clave (creación, expiración y última actualización del registro).

  • Los servidores de nombres (Name Servers) que usa el dominio (ej. ns1.google.com).

  • El Estado del Dominio (Domain Status), que suele ser clientTransferProhibited para evitar transferencias no autorizadas.

3. Dominio con privacidad (Ej. WordPress)

A veces es útil ver un dominio que usa un servicio de privacidad para enmascarar los datos personales del registrante, aunque la consulta sigue funcionando:

whois wordpress.com

  • En lugar de un nombre personal o de la empresa, es probable que veas información genérica o de un servicio de privacidad (como "Privacy Protection Service"). Esto demuestra cómo los registrantes protegen su identidad.

mtr - Diagnóstico de Ruta de Red

mtr (My Traceroute) es una poderosa herramienta que combina las funciones de ping y traceroute. Muestra continuamente la ruta a un destino, junto con estadísticas de latencia y pérdida de paquetes en cada salto (router intermedio).

Opciones Comunes

Opción Descripción
-n Muestra direcciones IP numéricamente.
-c <N> Envía N paquetes (en lugar de ejecutarse indefinidamente).
-r Muestra la salida en modo informe (report) y termina.

Ejemplos Prácticos

  1. Diagnóstico continuo de la ruta a Google:

Esto se ejecuta en tiempo real hasta que presionas 'q' o Ctrl+C. Observa las estadísticas en cada router.

mtr google.com

  1. Generar un informe de ruta con 10 paquetes y salir:

Útil para compartir un diagnóstico rápido y concreto.

mtr -r -c 10 8.8.8.8

vnstat - Monitor de Tráfico de Red

vnstat es un monitor de tráfico de red basado en consola que mantiene un registro del tráfico de red para las interfaces seleccionadas. Los datos de uso se almacenan en una base de datos y se utilizan para generar informes por hora, día o mes.

Pasos Necesarios (Instalación y Setup)

  1. Instalar vnstat:

sudo apt update && sudo apt install vnstat

  1. Identificar la interfaz (ej. ens33 )

  2. Inicializar la base de datos (requiere sudo):

sudo vnstat -u -i ens33

Ejemplos Prácticos

  1. Ver un resumen del tráfico actual/diario/mensual (el uso más común):

Vnstat

  1. Mostrar las estadísticas de tráfico por hora:

Muestra cuánto tráfico se ha usado en las últimas horas.

vnstat -h

  1. Monitoreo en tiempo real (similar a top):

Muestra la velocidad de transmisión y recepción actual hasta que presionas Ctrl+C.

vnstat -l

Comandos de Red Fundamentales en Linux

Los comandos ifconfig, route, mii-tool e iwconfig son considerados obsoletos o se han movido a herramientas modernas (como ip e ss).

Usuario: jose

Máquina: Ubuntu 24.04

Interfaz de Red Principal: eth0

  1. Configuración y Estado Básico de Interfaces (ifconfig, ifup/ifdown, dhclient)

Comando Descripción Requisitos
ifconfig eth0 Muestra la configuración de la interfaz eth0. Instalación de net-tools
ifup eth0 / ifdown eth0 Activa o desactiva la interfaz eth0. Permisos sudo
dhclient eth0 Fuerza a eth0 a obtener una IP por DHCP. Permisos sudo, dhcp-client

Ejemplos Prácticos con eth0

  1. Mostrar la configuración de la tarjeta de red eth0:

ifconfig eth0

  1. Configurar una dirección IP estática en eth0:

Esto asigna la IP 192.168.1.1 con máscara de subred 255.255.255.0 a la interfaz.

sudo ifconfig eth0 192.168.1.1 netmask 255.255.255.0

  1. Configurar eth0 en modo Promiscuo (para Sniffing):

Permite a la interfaz capturar todo el tráfico del segmento de red, no solo el dirigido a ella.

sudo ifconfig eth0 promisc

El comando sudo ifconfig eth0 promisc se utiliza para poner la interfaz de red eth0 en Modo Promiscuo (Promiscuous Mode).

Uso principal (Sniffing o Análisis de Red)

El uso principal de este comando es permitir que la interfaz de red (eth0 en este caso) capture absolutamente todo el tráfico que pasa por el segmento de red al que está conectada, no solo los paquetes que están dirigidos a su propia dirección MAC o IP.

¿Por qué es necesario?

Normalmente, una tarjeta de red (NIC) opera en Modo No-Promiscuo (el modo estándar). En este modo, el hardware de la tarjeta filtra a nivel bajo (capa 2) y descarta automáticamente:

  • Paquetes que no tienen como destino su propia dirección MAC.

  • Paquetes que no son de broadcast (dirigidos a todos, como ARP) o multicast (dirigidos a un grupo).

Al ejecutar sudo ifconfig eth0 promisc:

  1. Se desactiva ese filtrado del hardware.

  2. La interfaz le dice al sistema operativo: "Pásame todos los paquetes que vea, sin importar el destinatario".

  3. Esto es fundamental para herramientas de análisis de red (sniffers) como Wireshark o tcpdump, ya que necesitan ver el tráfico que circula entre otras máquinas en el mismo segmento de red (por ejemplo, en un switch antiguo o en una red Wi-Fi).

Uso Descripción
Análisis de Red (Debugging) Para diagnosticar problemas de conexión o latencia, viendo exactamente qué paquetes se están enviando entre dos dispositivos.
Seguridad Informática Se utiliza para detectar ataques, monitorizar la actividad maliciosa o, en el contexto de pruebas de penetración, para capturar credenciales o datos sensibles que viajan sin cifrar.
Monitoreo de Carga Para medir con precisión la carga total de tráfico que pasa por un segmento de la red, independientemente de los destinos específicos.

Nota: En redes modernas con switches inteligentes, es posible que el Modo Promiscuo solo capture el tráfico que el switch decide enviarle (que suele ser solo el tráfico dirigido a tu máquina). Para capturar todo el tráfico en una red conmutada, a menudo se requiere configurar un puerto espejo (SPAN) en el switch.

Para volver al modo normal:

sudo ifconfig eth0 -promisc

  1. Activar la interfaz eth0 en modo DHCP (obtener IP automática):

sudo dhclient eth0

2. Gestión de Enrutamiento (route)

Comando Descripción Requisitos
route -n Muestra la tabla de enrutamiento con IPs numéricas. Instalación de net-tools
route add Agrega una entrada de ruta. Permisos sudo
route del Elimina una entrada de ruta. Permisos sudo

Ejemplos Prácticos

  1. Mostrar la tabla de recorrido (enrutamiento):

route -n

  1. Configurar una ruta predeterminada (Gateway):

Esto indica a dónde enviar el tráfico que no tiene una ruta específica. Reemplaza 192.168.1.1 con la IP de tu router (IP_Gateway).

# 1. Eliminar la ruta predeterminada existente (si la hay)

sudo route del 0/0 gw 192.168.1.1

# 2. Configurar la nueva entrada predeterminada

sudo route add -net 0/0 gw 192.168.1.1

  1. Configurar una ruta estática para una subred específica:

Indica que cualquier tráfico para la red 192.168.0.0/16 debe pasar por el gateway 192.168.1.1.

sudo route add -net 192.168.0.0 netmask 255.255.0.0 gw 192.168.1.1

  1. Activar el reenvío de IP (IP Forwarding):

Convierte la máquina en un router básico, permitiendo el paso de paquetes entre diferentes redes.

sudo echo "1" > /proc/sys/net/ipv4/ip_forward

3. Resolución de Nombres y Hostname

Comando Descripción Requisitos
hostname Muestra el nombre del host del sistema. Ninguno
host www.example.com Resuelve el nombre del host a una dirección IP (consulta DNS 1). dnsutils
nslookup www.example.com Resuelve el nombre del host a una dirección IP (consulta DNS 2). dnsutils

Ejemplos Prácticos

  1. Mostrar el nombre de la máquina:

hostname

  1. Buscar la IP de un dominio usando host:

host www.google.com

  1. Buscar la IP de un dominio usando nslookup:

nslookup www.google.com

4. Diagnóstico de Hardware y Enlace

Comando Descripción Requisitos
ip link show Muestra el estado de enlace de todas las interfaces (moderno). Ninguno
mii-tool enp0s3 Se usa principalmente para ver y manipular el estado del enlace y la velocidad de una interfaz de red. Obsoleto
ethtool enp0s3 Es una herramienta más moderna y completa para ver y modificar toda la configuración de la tarjeta de red (NIC), incluyendo velocidad, duplex, capacidades, estadísticas y más. Vigente

Ejemplos Prácticos

  1. Mostrar el estado de enlace de todas las interfaces (preferido):

ip link show

  1. Mostrar el estado de enlace (cable conectado) de eth0:

sudo mii-tool eth0

  1. Mostrar las estadísticas detalladas de la tarjeta de red eth0:

ethtool eth0

5. Conexiones, Servicios y Tráfico (netstat, tcpdump)

Comando Descripción Requisitos
netstat -tup Muestra conexiones TCP y UDP activas con sus PID/Programa. net-tools, sudo
netstat -tupl Muestra servicios de escucha (Listening) TCP/UDP con sus PID/Programa. net-tools, sudo
tcpdump tcp port 80 Muestra todo el tráfico TCP dirigido al puerto 80 (HTTP). tcpdump, sudo

Ejemplos Prácticos

  1. Mostrar todas las conexiones de red activas y sus PID:

sudo netstat -tup

  1. Mostrar todos los servicios de escucha de red en el sistema y sus PID:

sudo netstat -tupl

  1. Mostrar todo el tráfico HTTP pasando por eth0:

Se requiere sudo. Presiona Ctrl+C para detener la captura.

sudo tcpdump -i eth0 tcp port 80

6. Configuración Inalámbrica (iwlist, iwconfig)

Nota: Estos comandos se utilizan típicamente en interfaces inalámbricas como wlan0 o eth1 (como en el ejemplo), no en la interfaz principal eth0 si es cableada.

Comando Descripción Requisitos
iwlist scan Muestra las redes inalámbricas disponibles. wireless-tools, sudo
iwconfig eth1 Muestra la configuración de la tarjeta de red inalámbrica eth1. wireless-tools

Ejemplos Prácticos con eth1 (simulando interfaz inalámbrica)

  1. Mostrar las redes inalámbricas:

sudo iwlist eth1 scan

  1. Mostrar la configuración de la tarjeta de red inalámbrica eth1:

iwconfig eth1
