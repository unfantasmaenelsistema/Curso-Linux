Clonar un disco en Linux

Clonar un disco con dd es muy potente, pero también muy peligroso si te equivocas de dispositivo (puedes sobrescribir datos irreversiblemente).

Pasos para clonar un disco con dd

1. Identificar los discos

Primero, lista los discos conectados:

lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT

o

sudo fdisk -l

  • Ejemplo:

    • Disco origen: /dev/sda (el que quieres clonar).

    • Disco destino: /dev/sdb (el que recibirá la copia).

Asegúrate al 100% de cuál es cuál. El destino será sobrescrito.

2. Ejecutar la clonación

El comando básico es:

sudo dd if=/dev/sdX of=/dev/sdY bs=64K status=progress

  • if= → input file (disco origen).

  • of= → output file (disco destino).

  • bs=64K → tamaño de bloque (mejora velocidad).

  • status=progress → muestra progreso en tiempo real.

Ejemplo:

sudo dd if=/dev/sda of=/dev/sdb bs=64K status=progress

3. Sincronizar buffers

Al terminar, fuerza a que se escriba todo en disco:

sync

4. Verificar la clonación

Puedes comparar con cmp o sha256sum en bloques:

sudo cmp -n 1G /dev/sda /dev/sdb

(si no devuelve nada, los primeros 1 GB son idénticos).

Variantes útiles

  • Clonar a un archivo de imagen (en vez de a otro disco):

sudo dd if=/dev/sda of=/ruta/backup.img bs=64K status=progress

  • Restaurar desde la imagen:

sudo dd if=/ruta/backup.img of=/dev/sdb bs=64K status=progress

  • Comprimir al vuelo:

sudo dd if=/dev/sda bs=64K | gzip > backup.img.gz

Advertencias

  • Nunca ejecutes dd sin revisar dos veces los dispositivos (if y of).

  • El disco destino debe ser igual o mayor tamaño que el origen.

  • Haz pruebas primero con discos/USB pequeños en tu laboratorio antes de usarlo en producción.

El parámetro bs (Block Size)

El parámetro bs (Block Size) en el comando dd es crucial porque define la cantidad de datos que se leen del origen (if) y se escriben al destino (of) en una sola operación de E/S (Input/Output).

La elección de bs afecta directamente la velocidad de la copia. Un valor demasiado pequeño (como el predeterminado de 512 bytes) es muy ineficiente en hardware moderno.

1. Recomendación General y Estándar

En la gran mayoría de los escenarios de clonación de discos o USB en hardware moderno (SSD, NVMe, o HDD recientes), el mejor rendimiento se obtiene con valores grandes.

Escenario Valor de bs Recomendado Razón
Copia rápida de un disco o imagen completa (Uso más común) bs=1M o bs=4M Estos valores grandes minimizan la sobrecarga de E/S del sistema operativo, permitiendo que la caché del disco duro (si existe) y el controlador se optimicen.
Buena opción predeterminada y rápida bs=64K (El valor del ejemplo) Es un buen equilibrio y casi siempre ofrece una mejora masiva respecto al valor predeterminado de 512 bytes.

2. Escenarios Específicos

La configuración óptima de bs puede variar ligeramente dependiendo de lo que estés haciendo:

Escenario Configuración de bs Razón
Máximo rendimiento (Sistemas con mucha RAM) bs=16M, bs=32M, o bs=64M Si tienes mucha memoria RAM disponible, aumentar el bs a estos valores puede mejorar la velocidad al permitir que el sistema bufferice grandes bloques de datos antes de escribirlos. Sin embargo, en la práctica, las mejoras sobre 1M o 4M suelen ser mínimas o nulas.
Recuperación de datos de un disco defectuoso bs=4K o bs=8K Si el disco de origen (/dev/sdX) tiene sectores dañados, es mejor usar un tamaño de bloque pequeño que sea un múltiplo del tamaño del sector físico (generalmente 4096 bytes o 4K). Esto, combinado con conv=noerror,sync, minimiza la pérdida de datos alrededor de los sectores fallidos, aunque el proceso es mucho más lento.
Copia de cargadores de arranque (MBR/GPT) bs=512 Si solo quieres copiar una parte muy específica como el Master Boot Record (MBR), necesitas un bs pequeño (el tamaño de un sector antiguo) junto con el parámetro count. Ejemplo: bs=512 count=1.

Principio Clave

El principio general es:

Aumentar bs para aumentar la velocidad (rendimiento), y reducir bs para aumentar la precisión (recuperación de errores).

Para la mayoría de las operaciones de clonación, bs=1M o bs=4M es el valor más utilizado y práctico para optimizar la velocidad sin exagerar el uso de memoria.

Copiar la tabla de particiones

Para copiar solo la tabla de particiones (el esquema de particionamiento, generalmente las primeras 512 bytes del disco) y no todos los datos del disco, la mejor opción es usar el comando dd con un tamaño de bloque (bs) y un contador (count) muy específicos.

Comando Óptimo para Copiar la Tabla de Particiones

Asumiendo que quieres copiar el Master Boot Record (MBR) completo (que incluye el cargador de arranque y la tabla de particiones en los primeros 512 bytes):

sudo dd if=/dev/sdX of=/ruta/a/backup.mbr bs=512 count=1

Parámetro Valor Propósito
bs=512 Bytes Establece el tamaño del bloque a 512 bytes, que es el tamaño tradicional y estándar del MBR (incluida la tabla de particiones).
count=1 Bloque Indica a dd que copie solo un bloque. Al ser bs=512, esto significa que solo se copian los primeros 512 bytes del disco de origen (/dev/sdX).

Escenario Adicional: Copiar Solo la Tabla de Particiones (sin el Código de Arranque)

Si tu objetivo es ser extremadamente preciso y copiar solo la tabla de particiones (que comienza en el byte 446 del MBR y tiene 64 bytes de longitud), el comando sería más complejo, utilizando skip para omitir el código de arranque:

sudo dd if=/dev/sdX of=/ruta/a/tabla.bin bs=1 skip=446 count=64

Sin embargo, para la mayoría de las necesidades de copia de la estructura de particionamiento, el primer comando (bs=512 count=1) es el más sencillo, seguro y cubre todo lo necesario para restaurar el esquema de particiones del disco.

Establecer bs=400 para copiar la tabla de particiones no es la opción ideal y podría llevar a un resultado incompleto o incorrecto para la mayoría de los formatos de disco.

La Tabla de Particiones Necesita 512 Bytes

La razón es que la Tabla de Particiones Principal (en el caso de MBR) reside dentro del primer sector del disco, que es de 512 bytes.

Parámetro Valor Resultado con bs=400
bs=400 400 bytes dd leerá y escribirá bloques de 400 bytes.
count=1 (asumido) 1 bloque Solo copiaría los primeros 400 bytes del disco.

Problema: Si solo copias 400 bytes, te faltarían los últimos 112 bytes del sector, que contienen información vital, incluyendo:

  1. Parte de la Tabla de Particiones.

  2. La Firma del Final del MBR (0x55AA), que el sistema necesita para validar el sector de arranque.

La Opción Correcta (MBR)

Para copiar la estructura de particiones de un disco MBR, debes asegurarte de copiar el sector de arranque completo (512 bytes):

sudo dd if=/dev/sdX of=/ruta/a/backup.mbr bs=512 count=1

  • bs=512 garantiza que copias el sector lógico completo de la forma más precisa y universal para esta tarea.

Nota sobre Discos Modernos (GPT/4K Sectores)

Aunque los discos modernos utilizan a menudo sectores físicos de 4096 bytes (4K) y el esquema GPT, la interfaz que presenta el sistema operativo (sector lógico) es, por compatibilidad, todavía de 512 bytes. Por lo tanto, bs=512 sigue siendo la mejor práctica para copiar solo la tabla de particiones.
