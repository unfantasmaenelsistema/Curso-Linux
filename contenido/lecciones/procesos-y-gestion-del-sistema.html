1. Comandos de Monitoreo y Estado de Procesos

Estos comandos te permiten ver qué está haciendo tu sistema y cómo se están utilizando los recursos.

ps: Reportar una Instantánea de los Procesos

El comando ps (process status) muestra los procesos que se están ejecutando en el momento en que se ejecuta el comando.

OpciónDescripción
auxMuestra todos los procesos (a), incluyendo los que no tienen terminal de control (x), con formato de usuario estándar (u).
efMuestra todos los procesos (e) con formato completo (f), útil para ver la línea de comandos completa y la jerarquía de procesos.

Ejemplo Práctico: Ver los procesos

Para ver todos los procesos que pertenecen al usuario jose:

ps aux | grep jose
jose 1234 0.0 0.1 123456 4568 ? Ss 07:08 0:00 /usr/bin/gnome-shell
jose 5678 0.0 0.0 12300 1024 pts/0 R+ 07:08 0:00 grep --color=auto jose

Ejemplo Práctico: Ver la jerarquía (árbol) de procesos

ps ef
UID PID PPID C STIME TTY TIME CMD
...
root 654 2 0 07:05 ? 00:00:00 /usr/lib/systemd/systemd --user
jose 1234 654 0 07:06 ? 00:00:01 \_ /usr/bin/gnome-shell
...

top: Monitor de Procesos Dinámico

El comando top proporciona una vista dinámica y en tiempo real de la actividad del sistema, incluyendo el uso de CPU, memoria y los procesos que más consumen. Es interactivo.

Ejemplo Práctico: Ejecutar y utilizar top

top

Una vez dentro de top:

  • Presiona M para ordenar por uso de memoria.
  • Presiona P para ordenar por uso de CPU (es el predeterminado).
  • Presiona k (kill) para terminar un proceso (te pedirá el PID).
  • Presiona q para salir.

htop: Monitor de Procesos Interactivo (Mejorado)

htop es una alternativa a top más moderna y visualmente amigable, que permite desplazarse horizontal y verticalmente, e interactuar con los procesos de forma más intuitiva.

Nota: En Ubuntu 24.04, podría necesitar instalación:

sudo apt install htop

Ejemplo Práctico: Navegar en htop

htop

Una vez dentro de htop:

  • Las barras de CPU y Memoria están claramente visibles en la parte superior.
  • Utiliza las flechas de dirección.
  • Presiona F6 para ordenar los procesos por cualquier columna.
  • Presiona F9 para enviar una señal de terminación (kill).
  • Presiona F10 o q para salir.

2. Comandos de Control de Trabajos (Job Control)

Estos comandos gestionan procesos que has iniciado en tu shell y que se han movido a segundo plano o se han detenido.

jobs: Listar Trabajos de la Sesión

El comando jobs muestra una lista de los trabajos (comandos) que están actualmente activos y asociados a tu sesión de terminal.

Pasos de Ejemplo: Crear y listar trabajos

Puedes usar el comando sleep con un tiempo mucho más largo o un bucle infinito para simular un proceso que no termina hasta que lo detienes. Luego, puedes usar los comandos para gestionar trabajos (jobs, fg, bg).

1. Iniciar un Proceso en Segundo Plano (&)

Inicia un proceso que tardará mucho tiempo en ejecutarse y envíalo inmediatamente a segundo plano (background) usando el símbolo &.

  1. Comando:
sleep 3600 &
  1. Explicación: Esto inicia el comando sleep para que espere 3600 segundos (1 hora). La & al final hace que el shell no espere a que termine y te dé el control de la terminal de inmediato.
  2. Salida Típica (ejemplo):
[1] 12345
  • [1] es el número de trabajo (Job ID).
  • 12345 es el ID de proceso (PID).

Si le pedimos que muestre los trabajos:

jobs

sleep 3600 (Running / Ejecutándose)

2. Iniciar un Proceso en Primer Plano y Detenerlo (Ctrl+Z)

Inicia un proceso interactivo que se ejecute en primer plano (foreground), y luego detenlo. Usaremos nano como ejemplo.

  1. Comando:
nano prueba.txt
  1. Acción: nano se abrirá
  2. Detener Proceso: Presiona las teclas Ctrl + Z (mantén Ctrl presionado y luego presiona Z). Esto enviará una señal SIGTSTP al proceso, deteniéndolo y pasándolo a la lista de trabajos.
  3. Salida Típica (ejemplo):
^Z
[2]+ Stopped nano prueba.txt
  • [2] es el número de trabajo del editor nano.
  • El signo + indica que es el trabajo que se usará por defecto si no especificas un número (el trabajo "actual").
  • Trabajo 2: nano prueba.txt (Stopped / Detenido)

[ Para suspender, teclear ^T^Z ]

En la notación de terminal y en muchos editores de texto basados en consola (como nano), el símbolo ^ (circunflejo) siempre significa la tecla Ctrl (Control).

Por lo tanto, la combinación de teclas que nos está pidiendo es:

  1. Mantener presionada la tecla Ctrl.
  2. Presionar la tecla T.
  3. Presionar la tecla Z.

¿Qué hace esta combinación?

Esta combinación de tres teclas (Ctrl+T seguido de Z) es una característica avanzada de nano que te permite suspender el proceso de nano (enviarlo al background como un trabajo detenido) después de haber activado un modo especial de atajo de teclado dentro de nano.

Normalmente, para suspender nano y enviarlo al background, solo necesitas presionar Ctrl + Z directamente.

Pero que en la versión o configuración que estamos usando, han introducido un paso extra de seguridad o un atajo de teclado para evitar suspenderlo accidentalmente, pidiendo primero Ctrl+T y luego el atajo de suspensión normal (Ctrl+Z).

Intenta la combinación completa:

  1. Ctrl + T
  2. Z (justo después de Ctrl+T)

Esto debería suspender el proceso de nano y devolvernos a la línea de comandos de nuestra shell, permitiéndonos usar el comando jobs para verlo como un trabajo detenido.

3. Listar los Trabajos

Usa el comando jobs para ver el estado de todos los procesos que has iniciado y que están siendo gestionados por tu shell.

  1. Comando:
jobs
  1. Salida Típica (ejemplo):
  2. [1]- Running sleep 3600 &
  3. [2]+ Stopped nano prueba.txt
    • Observarás que el trabajo [1] está Running (ejecutándose en segundo plano).
    • Observarás que el trabajo [2] está Stopped (detenido).

Comandos Adicionales Útiles (Gestión de Trabajos)

  • fg %N: Pone un trabajo detenido o en segundo plano de nuevo en primer plano (foreground). Reemplaza N con el número de trabajo (e.g., fg %2 para reanudar y trabajar en nano prueba.txt).
  • bg %N: Continúa un trabajo detenido en segundo plano (background). Reemplaza N con el número de trabajo (e.g., bg %2 para que nano se ejecute en background, aunque como es interactivo, generalmente no es útil).
  • kill %N: Termina un trabajo de forma forzosa. Reemplaza N con el número de trabajo (e.g., kill %1 para detener sleep 3600).

fg: Traer un Trabajo a Primer Plano

El comando fg (foreground) trae un trabajo que está detenido o en segundo plano de vuelta al primer plano, permitiéndote interactuar con él.

Ejemplo Práctico: Reanudar nano

jobs
[1]- Running sleep 60 &
[2]+ Stopped nano ejemplo.txt
fg %2
# El %2 se refiere al ID del trabajo [2]

(Se abre el editor nano para que jose continúe editando el archivo.)

bg: Poner un Trabajo en Segundo Plano

El comando bg (background) reanuda un trabajo detenido y lo mueve para que se ejecute en segundo plano.

nano prueba.txt

Ejemplo Práctico: Enviar nano a segundo plano

Si nano está detenido (como en el ejemplo de jobs):

jobs
[1]- Running sleep 60 &
[2]+ Stopped nano ejemplo.txt
bg %2
[2]+ nano ejemplo.txt &
jobs
[1]- Running sleep 60 &
[2]+ Stopped nano ejemplo.txt &

La razón por la que nano sigue apareciendo como Detenido después de ejecutar bg %2 es que nano es un editor de texto interactivo en modo consola.

Cuando envías un trabajo detenido (Stopped) a segundo plano (bg), el shell intenta reanudarlo para que pase a estado ejecutándose (Running). Sin embargo, en el caso de programas interactivos como nano, el núcleo (kernel) lo vuelve a detener inmediatamente.

Cuando un proceso está detenido (Stopped), el comando bg %N lo envía a segundo plano (background) para que continúe su ejecución.

  1. Procesos sin Interacción (como sleep):
    • Comandos como sleep 3600 pueden ejecutarse completamente en segundo plano, ya que no necesitan interactuar con el usuario o el terminal. Por eso el trabajo [1] aparece como Ejecutando (Running).
  2. Procesos Interactivos (como nano):
    • nano está diseñado para leer la entrada del teclado y escribir en la pantalla del terminal (interactuar con el TTY).
    • Un proceso que intenta leer datos de la terminal o escribir directamente en ella mientras está en segundo plano es automáticamente detenido por el sistema operativo (kernel de Linux) para evitar que "cuelgue" la terminal o mezcle su salida con la línea de comandos.

Lo que sucedió:

  1. Ejecutamos bg %2 para reanudar nano en segundo plano.
  2. El shell intenta iniciar la ejecución de nano.
  3. nano intenta dibujar su interfaz en la terminal.
  4. El kernel detecta que un trabajo en segundo plano (nano) está intentando acceder a la terminal.
  5. El kernel detiene inmediatamente el proceso (nano) y le envía la señal SIGTTIN o SIGTTOU (señales de Entrada/Salida de Terminal).
  6. Por eso, cuando vuelves a ejecutar jobs, el estado de [2] vuelve a ser Detenido (Stopped), a pesar del intento de reanudarlo.

Para interactuar con nano o cualquier otro programa interactivo que hayas detenido, siempre debes traerlo de vuelta al primer plano (foreground).

  • Utiliza el comando:
fg %2

Esto devolverá el control de la terminal al proceso de nano para que puedas continuar editando el archivo prueba.txt.

Nota: nano no es ideal para el segundo plano ya que espera entrada de usuario, pero el ejemplo ilustra la función del comando.

3. Comandos de Señalización de Procesos

Estos comandos se utilizan para enviar señales a los procesos. La señal más común es SIGTERM (terminación "elegante") y SIGKILL (terminación forzada).

kill: Enviar Señales a un Proceso por PID

El comando kill envía una señal a un proceso identificado por su PID (Process ID).

OpciónSeñalDescripción
(ninguna)SIGTERM (15)Pide al proceso que termine "elegantemente" (el proceso puede limpiar antes de salir).
-9SIGKILL (9)Termina el proceso inmediatamente sin permitirle guardar o limpiar.

Ejemplo Práctico: Terminar un proceso elegantemente

  1. Usa sleep 1000 para generar un proceso con un PID conocido (ej. 12345).
  2. Usa kill para terminarlo.
sleep 1000 &

[1] 12345 # Este es el PID (Process ID)

kill 12345 # Se envía SIGTERM
[1]+ Terminated sleep 1000

Ejemplo Práctico: Terminación forzada (SIGKILL)

Si el proceso 12346 no responde a SIGTERM, usa -9:

sleep 1000 &
[1] 12346
kill -9 12346
[1]+ Killed sleep 1000

killall: Enviar Señales a Procesos por Nombre

El comando killall es útil para terminar todos los procesos que coinciden con un nombre de comando específico.

Ejemplo Práctico: Cerrar todas las instancias de un programa

Si tienes varias ventanas de gedit abiertas:

killall gedit

(Esto envía SIGTERM a todos los procesos llamados gedit.)

Puedes probar el efecto del comando killall gedit de la siguiente manera:

Pasos para Probar killall gedit

sudo apt install gedit
  1. Abre Múltiples Ventanas de gedit

Abre varias instancias del editor de texto gedit desde tu terminal o interfaz gráfica. Puedes hacer esto desde la terminal con el comando:

gedit archivo1.txt &

gedit archivo2.txt &

gedit archivo3.txt &

(El & al final envía cada instancia a segundo plano para que puedas seguir usando la terminal).

  1. Verifica que los Procesos se están Ejecutando

Usa el comando pgrep para listar los IDs de proceso (PID) que se llaman gedit.

pgrep gedit

Deberías ver una lista de números (los PID de tus ventanas de gedit).

  1. Ejecuta killall gedit

Este comando enviará la señal SIGTERM (señal de terminación) a todos los procesos que se llaman gedit.

killall gedit
  1. Observa el Resultado
    • En la interfaz gráfica: Todas las ventanas de gedit deberían cerrarse casi instantáneamente. Si tenías cambios sin guardar, gedit podría mostrar una advertencia o intentar guardar automáticamente, dependiendo de su configuración, pero el proceso en sí habrá recibido la señal para terminar.
    • En la terminal: Si ejecutaste las ventanas en segundo plano, la terminal podría mostrar mensajes como "Terminated" o "Exited" para cada trabajo.
  2. Verifica la Terminación de los Procesos

Vuelve a usar pgrep para confirmar que ya no quedan procesos llamados gedit.

pgrep gedit

Esta vez, el comando no debería devolver ninguna salida, confirmando que todos los procesos fueron terminados con éxito.

killall gedit

Este comando envió la señal SIGTERM (terminación suave) a todos los procesos llamados gedit. Estos procesos inmediatamente comenzaron a cerrarse.

Ejecución de pgrep gedit y la respuesta del Shell:

pgrep gedit
[2]+ Terminado gedit archivo1.txt
  • Salida de pgrep gedit: Como no aparece ningún número (PID) encima del mensaje del shell, significa que pgrep no encontró ningún proceso gedit ejecutándose. Esto demuestra que el killall fue exitoso y todos los procesos terminaron.
  • Mensaje del Shell: El mensaje [2]+ Terminado gedit archivo1.txt no es la salida de pgrep, sino una notificación que te da el shell (Bash) justo en ese momento. Cuando ejecutamos pgrep, el shell detectó que el trabajo número [2] (gedit archivo1.txt) ya había finalizado su ejecución (fue Terminado por el killall).

Ejemplo Práctico: Terminación forzada por nombre

killall -9 firefox

(Termina forzadamente todas las instancias de firefox.)

4. Comandos de Prioridad de Procesos

Estos comandos permiten modificar la prioridad con la que el kernel de Linux asigna tiempo de CPU a un proceso. La prioridad se mide con el valor niceness (rango de -20 a 19).

  • -20: Máxima prioridad (menos "nice").
  • 19: Mínima prioridad (más "nice").
  • 0: Prioridad por defecto.

nice: Ejecutar un Comando con Prioridad Modificada

El comando nice se usa para iniciar un nuevo proceso con una prioridad diferente a la predeterminada.

OpciónDescripción
-n NICE_VALOREspecifica el valor de niceness (ej. 10).

Ejemplo Práctico: Ejecutar un backup con baja prioridad

Quieres ejecutar un proceso de copia de seguridad (tar) para que no interfiera con su trabajo normal:

nice -n 15 tar -czf /tmp/backup_jose.tar.gz /home/jose/Documentos

(El valor 15 asegura que el proceso tar solo usará la CPU cuando otros procesos lo permitan.)

renice: Cambiar la Prioridad de un Proceso en Ejecución

El comando renice se usa para cambiar el valor de niceness de un proceso que ya está en marcha.

Ejemplo Práctico: Bajar la prioridad de un proceso

  1. Ejecuta una simulación (ej. sleep 3600) y obtiene su PID (ej. 12347).
  2. Baja su prioridad.
sleep 3600 &
[1] 12347
renice 10 -p 12347
12347 (process ID) old priority 0, new priority 10

5. Comando de Utilidad de Entrada

xargs: Construir y Ejecutar Líneas de Comandos

El comando xargs toma la entrada estándar (STDOUT), generalmente el resultado de otro comando (vía pipe |), y la utiliza para construir y ejecutar líneas de comando. Es esencial para trabajar con grandes listas de archivos.

OpciónDescripción
-I {}Define un marcador de posición ({}) para insertar cada línea de entrada.
-pPide confirmación antes de ejecutar cada comando.
-0Usar con find -print0 para manejar nombres de archivo con espacios o caracteres especiales.

Ejemplo Práctico: Borrar muchos archivos encontrados

Quieres borrar todos los archivos con extensión .bak en su carpeta:

1. Crear Archivos .bak

  1. Crear un archivo vacío con touch:
touch /home/jose/config.bak
  1. Crear otro archivo con contenido (usando echo y redirección >):
echo "Contenido de backup" > /home/jose/doc_viejo.bak

2. Verificar la Creación

ls /home/jose/*.bak

Salida esperada:

/home/jose/config.bak /home/jose/doc_viejo.bak

3. Ejecutar el Comando para Buscar y Eliminar

find /home/jose -name "*.bak" | xargs rm

Explicación del comando:

  • find /home/jose: Busca archivos empezando desde el directorio /home/jose.
  • -name "*.bak": Filtra la búsqueda solo para archivos cuyo nombre termina en .bak.
  • |: Es una tubería (pipe) que envía la salida del comando find como entrada al siguiente comando.
  • xargs rm: Toma la lista de nombres de archivo que recibe de find y ejecuta el comando rm (eliminar) con cada uno de ellos como argumento. En esencia, elimina todos los archivos encontrados.
find /home/jose -name "*.bak" | xargs rm

(find envía la lista de archivos a xargs, y xargs ejecuta rm con esa lista como argumentos.)

Ejemplo Práctico: Copiar archivos de forma segura e interactiva

Quieres copiar solo los archivos .png al directorio /tmp/imagenes_jose, pidiendo confirmación:

find . -name "*.png" -print0 | xargs -0 -I {} -p cp {} /tmp/imagenes_jose
cp ./foto1.png /tmp/imagenes_jose? ...y/n/..

(El uso de -print0 y -0 asegura que los nombres de archivo con espacios se manejen correctamente.)

4. kill – Terminar procesos por PID

Uso:

kill [señal] PID

Ejemplos prácticos:

Matar proceso con PID 1234:

kill 1234

Enviar una señal específica (ej: SIGKILL):

kill -9 1234

Enviar señal de parada (SIGTERM):

kill -15 1234

La principal diferencia entre usar kill -9 y kill -15 radica en la capacidad del proceso para realizar una limpieza antes de terminar, lo cual afecta la seguridad y estabilidad del sistema.

Característicakill -15 (SIGTERM)kill -9 (SIGKILL)
Señal EnviadaSIGTERM (Terminación, valor 15)SIGKILL (Muerte, valor 9)
ComportamientoGracioso (Cortés)Forzado (Brutal)
Manejo por el ProcesoEl proceso puede capturar e ignorar la señal, o, lo que es más común, ejecutar rutinas de limpieza (guardar archivos, liberar memoria, cerrar conexiones).El proceso no puede capturar, ignorar ni bloquear la señal. El kernel termina el proceso inmediatamente.
Limpieza de DatosSí, el proceso tiene tiempo de cerrar archivos y liberar recursos de forma ordenada.No, el proceso se detiene de golpe, lo que puede dejar archivos abiertos o datos corruptos.
Uso RecomendadoSiempre intenta usar -15 primero. Es la forma estándar y segura de terminar un programa.Solo como último recurso cuando -15 no funciona (e.g., el proceso está colgado o es un proceso zombie).

1. kill -15 (SIGTERM) - La Terminación "Graciosa"

SIGTERM significa "Signal Termination" (Señal de Terminación). Es la señal por defecto que envía el comando kill si no especificas un número.

  • Es una solicitud para que el proceso termine.
  • Permite al programa "limpiar": guardar el trabajo, cerrar conexiones de red, liberar recursos y cerrar archivos de forma segura.
  • Es el método preferido porque minimiza el riesgo de corrupción de datos o de dejar archivos temporales abiertos.

2. kill -9 (SIGKILL) - La Terminación "Forzada"

SIGKILL significa "Signal Kill" (Señal de Muerte).

  • Es un comando incondicional del núcleo (kernel) para eliminar el proceso.
  • El proceso muere inmediatamente sin posibilidad de guardar, limpiar o reaccionar de ninguna manera. Es como desconectar la alimentación de un ordenador.
  • Se utiliza solo cuando SIGTERM no funciona (es decir, el proceso está colgado o ignorando la señal de terminación). El riesgo es que puede dejar datos inconsistentes o archivos incompletos.

5. nice – Ejecutar proceso con prioridad modificada

Los valores van de -20 (más prioritario) a 19 (menos prioritario).

Uso:

nice -n [valor] comando

Ejemplos prácticos:

Ejecutar script con baja prioridad:

nice -n 10 python3 /home/jose/script_lento.py

Sin sudo solo puedes aumentar el valor (bajar prioridad).

6. renice – Cambiar la prioridad de un proceso ya en ejecución

Uso:

renice -n [nuevo_nice] -p [PID]

Ejemplo:

Cambiar el nice de un proceso con PID 1234 a 5:

sudo renice -n 5 -p 1234

7. jobs – Ver trabajos en segundo plano (solo en la terminal actual)

Uso:

jobs

Ejemplo:

jobs

8. fg – Traer un trabajo del fondo al frente

Uso:

fg %[número]

Ejemplo:

Traer el trabajo 1 al frente:

9. bg – Reanudar un trabajo detenido en segundo plano

Uso:

bg %[número]

Ejemplo:

Ejecutar en segundo plano un proceso suspendido con Ctrl+Z:

Uso:

Ejemplos prácticos:

11. xargs – Ejecutar comandos con salida de otro (muy útil en scripts)

Uso:

comando | xargs otro_comando

Ejemplos prácticos:

Eliminar archivos listados por find:

Abrir múltiples archivos con xdg-open:

locate "*.pdf" | head -n 3 | xargs xdg-open
